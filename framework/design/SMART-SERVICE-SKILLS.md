# 网页客户业务技能

`framework/skills/` 维护 10 个智能服务的办理指导。`catalog.json` 是 `serviceId` 到技能名的唯一映射；`framework/agent-services.json` 决定客户端展示哪些入口（当前 8 个常用项），其余技能仍由自动匹配加载，不在选择器里重复占位。网页发送消息时通过 `serviceIds` 提交本轮选择，服务端解析映射并使用原生显式调用加载完整技能；消息正文不拼接功能标题。

## 分工

- `SKILL.md`：适用请求、必要信息、办理步骤、结果和能力限制。
- `framework/knowledge/`：银行规则及网页操作，使用 `knowledge_lookup` 检索。
- 银行工具：查询实时数据、发起确认并办理；技能不能授予权限或代替确认。

未指定功能时，Agent 根据目录通过原生 `skill` 工具加载相关技能。用户输入 `/bank-transfer` 等名称可显式加载；跨功能可同时加载多个技能。技能加载记录随原生会话保存，正文不会全量塞进初始提示。只加入客户 profile，不影响员工和运维 Agent。

## 能力边界

8 个入口各自负责一段业务，重叠部分按下面的归属加载，避免同一个问题被两个技能反复办理：

| 入口 | 包含 | 不包含（归到哪） |
| --- | --- | --- |
| 智能转账 | 境内/跨境转账、FPS、到账查询、在途撤回、定时转账、AA 收付款 | 只换币种 → 换汇助手；卡设置与卡消费 → 银行卡管家 |
| 理财顾问 | 产品、风险测评、持仓、申赎，以及储蓄目标、定投、现金管理（储蓄子技能） | 保险保障 → 保险咨询 |
| 保险咨询 | 保障需求、保单与条款比较、保费测算、查询保单与投保 | 理赔、退保与承保承诺不在能力内；理财与储蓄 → 理财顾问 |
| 账单分析 | 流水、账单、月度/年度报告、预算、自动扣款与续费提醒 | 借款月供 → 借款测算；卡设置 → 银行卡管家 |
| 银行卡管家 | 申请、换卡、激活、锁卡、挂失、限额、支付开关、模拟消费、卡号/CVV | 账户余额与转账 → 智能转账；风险与密码设置 → 安全助手 |
| 换汇助手 | 账户内币种兑换、报价与成交 | 跨币种转账 → 智能转账；不新开户、不改账户号 |
| 借款测算 | 额度、月供、总利息、分期，以及工资与备用金 | 账单与支出历史 → 账单分析 |
| 安全助手 | 登录/支付密码、设备、冻结、异常与安全设置 | 实际锁卡/挂失/补卡 → 银行卡管家 |

未进选择器的两个技能：

- `bank-savings`：理财顾问的储蓄子项，只在自动匹配或从理财入口进入时加载，不单独占按钮；
- `bank-support`：网页操作、报错、人工客服与工单，按问题自动匹配；不替代任何业务技能，工单只登记问题，不代表已接通人工。

## 站内跳转卡片

助手需要让客户去某个页面办理（例如改密码、改手机号去安全中心）时，在回复里输出站内链接 `[前往安全中心](/security)`。网页把站内路径渲染成跳转卡片并做 SPA 跳转；其他渠道按普通链接展示。链接只允许站内路径（`/` 开头且不是 `//`），不输出 `javascript:` 等协议；助手不代办改密码、改手机号，也不索取密码或验证码。

## 能力清单接口

客户端的可选能力改由后端下发，统一读取 `GET /agent-api/services`（需登录令牌）。网页已接入，`app/src/components/layout/services.ts` 只保留图标与页面归属；安卓接入是后续改动：

```json
{
  "version": 1,
  "updatedAt": "2026-11-01",
  "services": [
    { "id": "transfer", "order": 10, "label": "智能转账", "description": "转账、FPS、到账查询与撤回" }
  ]
}
```

- 唯一来源是 `framework/agent-services.json`，Agent 启动时读取并校验；改完需重启 Agent，不做热更新。网页只保留图标与路由映射，不再维护文案和条目；安卓接入后同样。
- 每项只有 `id`、`order`、`label`、`description`：图标、路由归属和 docked 上下文是客户端表现，客户端按 `id` 自行映射。
- `id` 必须能在 `catalog.json` 找到同名技能，`label` 必须与技能头部 `metadata.label` 一致；`npm run skills` 校验这条一致性。
- 清单是技能目录的子集，可以少于技能数；被移除的入口仍可被自动匹配加载，历史消息里的 `serviceIds` 也继续有效。
- 响应只含展示元数据，不含模型、密钥、客户或价格信息。

## 网页消息接口

`POST /agent-api/sessions/:id/messages` 保留现有文字、图片与登录鉴权，新增可选 `serviceIds: string[]`，例如 `["transfer", "cards"]`。只允许技能目录中的功能 ID（可以多于展示清单，兼容历史选择），至多 10 项，重复项合并；任意技能名或路径、非数组和未知 ID 返回 `400 INVALID_SERVICE_SELECTION`，不会入队。

未传字段兼容旧客户端，传空数组表示清除选择，两者都恢复按当前问题自动匹配。选择只影响本轮指导，不视为办理授权；历史已加载技能可以继续作为上下文，但历史选择不构成本轮办理指令。选择快照随本地用户消息保存，编辑或重新生成沿用原消息选择。工作人员接口不接受此客户字段。

## 修改与验证

修改对应 `SKILL.md` 和测试断言，同步维护 YAML 头部的工具、路由与依据文件。新增技能还需修改映射；只有需要固定入口的技能才同时加进网页 `services.ts`，并保持 id、标签与技能头部一致。维护说明放在本文件，不要在技能扫描目录放 README.md 等平铺 Markdown，以免被原生提供方当作技能解析。

每篇正文上限 6000 UTF-8 字节，目录描述上限 180 字；超出必须精简，不能截掉条件。

在 `framework/` 执行：

```sh
npm run skills
npm run test:services
npm run test:skills
bash scripts/bootstrap.sh
npm run test:skills:e2e
```

构建和 bootstrap 均自动校验。bootstrap 按项目现有机制安装本地技能 bundle，仅使用仓库内隔离 profile；不改个人技能目录。文件提供方关闭默认目录与监视，只从指定仓库技能目录读取；更新后重启客户 Agent，不给模型开放普通文件读取权限。

60 条固定案例覆盖口语、缺信息、多技能和能力边界。端到端夹具使用本地模型协议、真实 Harness 和临时 SQLite，验证目录、完整正文、功能 ID 多选与清除、非法输入、显式加载、重启、确认与流式通道；**不表示真实模型的意图识别准确率**。脚本不使用远端客户数据，也不调用付费模型。

## 发布

本轮只做本地实现。后续发布应一起带上技能目录、技能 bundle、profile 模板及更新后的 bootstrap，先校验再重启客户 Agent。旧会话保留已加载的正文；修改规则后应新建会话验证，已发起的银行授权仍按既有有效期和状态校验。

独立换汇、储蓄目标、借款及保险缺少 Agent 办理工具，当前技能只提供解释、分析或页面引导。以后增加工具时，同一提交更新对应能力限制和测试，不能先在技能里声称已支持。
