# P3：安全收尾（加固包）——已验证

> 2026-09-17。三件事：工具结果脱敏、工具白名单单调守卫、遥测导出脱敏。
> 结论：**前两件端到端通过**（含"密钥没进模型也没进日志"这种硬断言），第三件按部署可选。

## 1. 交付物

包 `packages/hardening`（`@luckycat/dsh-hardening`）：

| 文件 | 职责 |
|---|---|
| `src/redact.ts` | 脱敏规则：**按环境变量取值**（配置里只写变量**名**）+ 内置形态（`sk-…`、Bearer、赋值式、AWS、PEM）；另有 `redactDeep` 用于结构化记录 |
| `src/guard.ts` | 白名单守卫的纯逻辑：名单外一律拒绝，拒绝理由按**模型视角**写清可用工具 |
| `src/index.ts` | 接线：`tools/post-execute` 脱敏 + `ctx.tools.guard` + 可选遥测脱敏 |

## 2. 三个机制为什么这样选

1. **在结果成为 durable 事件之前脱敏**。DSH 的规范化会话日志按设计**永不重写**，
   所以"事后清洗日志"这条路根本不存在。`tools/post-execute` 是**唯一**
   能在落盘与进模型之前改投影的地方——也就是 DSH 说的"在做出决定的那一步执行"。
2. **白名单而不是黑名单**。黑名单永远漏（新插件可以起任意工具名）。
   白名单让"新增一个能力"变成**一次显式动作**（改配置），正是"框架无 shell"的口径。
3. **只收紧**。DSH 的 `ctx.tools.guard()` 保证后续监听者**不能把已被拒绝的调用改成允许**，
   所以这一层是单调的。

## 4. 踩到的两个坑（都值得记住）

### 4.1 安全监听器**抛异常会让 waterfall 静默退回原结果**

第一版脱敏在监听器里调了 `ctx.logger.warn(...)`。而 **sdk-minimal 那棵树不挂 logger**
（`ctx.logger` 来自 `@deepseek-ai/cordis-plugin-logger-console`，只有测试夹具挂它），
于是那句调用抛异常 → waterfall 退回原结果 → **脱敏完全失效，且没有任何报错**，
端到端测试里密钥照样进了日志与模型。

两个修法都做了：

- 日志改成**可选服务**式读取（`ctx.logger?.warn?.()`）；
- 监听器整体包 `try/catch`，**失败即 fail-closed**：宁可 `block` 掉这次结果，
  也绝不放行可能带密钥的原文（"脱敏失败"绝不能变成"不脱敏"）。

### 4.2 `tools/post-execute` 给的是**尚未渲染的 `value`**

`PostToolDecision` 的两个 `accept` 变体是 `content?` 与 `value?`（互斥）。
工具返回字符串时默认给的是 `value`，我第一版只处理 `content` → 整段跳过脱敏。
正确写法照 DSH 自己的 `spill-policy`：`value` / `content` / 退回 `result.content` 三种都要处理，
并且用 `{ prepend: true }` 处在外层。

## 5. 测试证据

- 离线单测 **17 个**：形态脱敏、按取值脱敏、正则元字符、规则状态残留、
  深层脱敏、守卫放行/拒绝/空名单、非法正则加载期报错。
- 变异测试：把 `redactText` 改成"报命中但不改文本"（脱敏空操作）→
  **安全端到端 6 条断言全部失败**；恢复后 17/17。
- 验收门：离线 **51 条**；端到端为可选门（`LUCKYCAT_E2E=1`，含知识库问答与安全两组）。

## 6. 未做 / 已知限制

- **遥测导出脱敏未经端到端验证**：本框架的树没挂 telemetry，所以那条监听器是"备好待用"，
  只有 `redactDeep` 的纯函数被单测覆盖。真接 telemetry 时要单独验一次。
- `try/catch` 的 fail-closed `block` 分支**没有被测试实际触发**（只是实现了）；
  要有意构造一次"脱敏必炸"的场景才能验。
- 守卫在**执行时**拒绝，工具对模型仍然可见（`restrict()` 只能在 scoped ctx 里用）。
  也就是说模型可能先看到工具、调用后才被拒——我们选择"理由写清楚"而不是隐藏。
- 白名单是全局的，没有按 agent/会话细分。
- 脱敏是"模式 + 已知取值"匹配，不是数据分类；未知形态的密钥仍可能漏。
  真正的防线仍是"不让密钥进工具输出"。
