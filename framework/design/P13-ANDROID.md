## 是什么

把现在这个**只给桌面浏览器**的前端，做一个安卓原生版。为什么单独做原生而不是
把 web 改成响应式：

- 现有前端 **0 个响应式断点**——它压根不是"窄一点"就能用的东西，是照桌面宽度
  排的版。改成手机版等于重排一遍，而重排完还是网页。
- **语音是重点，而语音在原生上更强**：`AudioTrack` 直接喂 PCM16 就没有浏览器那套
  自动播放策略（`playBlocked` / 用户手势解锁）；`MediaRecorder` 的容器格式也比
  浏览器的 `webm` 更好对上桥接的 ASR 映射。
- 手机端要的是"能揣兜里用"，PWA 在安卓上仍然会受浏览器策略与后台限制。

**App 只实现 `P6` / `P8` 已经文档化的接口面，桥接一行不改。** 这是这一层的意义：
换客户端不动后端。

## 四块硬骨头

### 1. 流式语音（安卓这边反而简单）

`POST /agent-api/tts/stream` 是 SSE：`start{format:'pcm',sampleRate}` → `audio`×N
（裸 PCM16 LE 的 base64）→ `end{frames,bytes,truncated}`，失败回 `error{message}`。

安卓侧：每帧 base64 解码 → **`AudioTrack`（24000Hz / mono / PCM16）直接 write**，
首帧到达就出声。比 Web Audio 那套少了自动播放策略，但**必须照搬 web 端踩出来的三条**：

| 坑 | 结论 |
| --- | --- |
| 取消 ≠ 失败 | 用户主动停要静默，真失败要上报。web 端的 bug 是 `teardownPlayback()` 先 abort 了 controller，再读 `signal.aborted` 永远是 true，**真失败被吞掉**。安卓侧要在关流之前先记 `wasAborted` |
| 波形在整段合成完之后才算 | 不要边收边算 |
| 说话不能算数 | 见下 §3 |

按住说话：`MediaRecorder` → AAC/MP4 → base64 → `POST /agent-api/asr`。
桥接按 MIME 映射格式（`audio/mp4→m4a`、`audio/aac→aac`），**安卓默认产出哪种容器
要真机验一遍**，这是没验过的一条。

### 2. 确认通道 / 提问通道

`consent` 事件带 `challenge`，用户作答走 `POST /agent-api/consent/:challengeId`
`{ decision, paymentPassword? }`；提问走 `POST /agent-api/questions/:questionId/answer`。
**这两个都是"答完才放行长轮询"**，所以客户端不能超时就当拒绝——超时语义见 `P5` / `P12`。

### 3. 安全：支付密码绝不进 agent

照 `P5-CONSENT.md`：**展示交易信息 → 用户确认 → 输入支付密码 → 才执行**，
密码只发桥接，绝不进对话、绝不进模型上下文。**语音只提醒，不代答**。

这是整个原生重写里风险最高的一块，也是 web 端门禁最多的一块
（`check-agent.mjs` 51 条里大半是它）。安卓侧必须单独写门禁，不能靠"看起来对"。

### 4. 测试（原生重写最大的代价，先认账）

web 端那套 Playwright 门禁（100+ 断言）**对不上原生**。重来，但分两层：

- **契约测试（最值钱，纯 JVM，不需要模拟器）**：直接打桥接 `/agent-api/*`，
  断言响应形状、SSE 事件序列、consent 通道。**web 端和安卓端跑同一份**——
  桥接契约一改，两端同时红。这一层能立刻跑，是第一步就做的理由。
- **安卓 UI 测试**：Compose UI Test（模拟器）+ 真机冒烟（语音、录音、音频焦点）。
  门禁思想照搬 web：**用 `testTag` 当锚点**（等价于 web 的 `data-*`），
  每条新门禁都做变异验证，空断言要标注出来。

## 联调与部署

- **桥接现在只监听 `127.0.0.1`**（`demo-server.mjs` 的 `server.listen(PORT, '127.0.0.1')`），
  真机连不上。联调要改绑 `0.0.0.0`。
- 访问口令**已经有了**，不用新做：服务端 `LUCKYCAT_DEMO_TOKEN` + 请求头
  `x-luckycat-token`，设了口令以后所有请求都要带（`demo-server.mjs` 里那段 401）。
  客户端这边 `AgentApi(token = …)` 已经把这个头带上。
  也就是说改绑 `0.0.0.0` 时**必须同时设 `LUCKYCAT_DEMO_TOKEN`**——
  把 demo-server 暴露到局域网而不设口令是不能接受的。
- 真机联调：手机与电脑同一 Wi-Fi，App 里把桥接地址配成 `http://<电脑局域网IP>:8788`。
  手机上的 `127.0.0.1` 是手机自己，模拟器访问宿主机才是 `10.0.2.2`。
- 明文 HTTP：只有 **debug** 构建允许（`app/src/debug/AndroidManifest.xml` 里的
  `usesCleartextTraffic`）。这是银行客户端，release 不该默认允许明文。
- 线上 `bank.waveflow.cn` 是**旧版本、完全没有语音**；要让手机端真正可用，
  最终要把新版前端 + 桥接一起重新部署。这不在本轮范围内，但别忘。

## 一条容易搞错的服务端语义（写进契约测试了）

确认通道上，**支付密码错误时服务端回 401 且「不结算」挑战**——用户还能再输一次
（`demo-server.mjs` 的 `answerConsent` 分支）。所以客户端必须把 401 当**重试**，
不能当"失败"把卡片收起来：收起来以后用户没有第二次机会，而 agent 那边还在等。
`AgentApiTest.确认通道的 401 是密码不对 不是终态` 钉的就是这条。

### 决定性的一条：`adb reverse` 不过数据，用 `10.0.2.2`

原来的计划是用 `adb reverse tcp:8788 tcp:8788` 让模拟器连宿主。**实测不行**：

- TCP **连接确实建立**（宿主起的回显服务器能看到 connection），
- 但**数据两个方向都过不去**（设备发的字节到不了宿主，宿主发的字节到不了设备），
- 对照实验排除了误判：不在设备上发请求时，宿主服务器**收不到任何连接**。

换成 `10.0.2.2`（QEMU 给宿主 loopback 的固定别名）**完全正常**：双向数据都对，
而且它能打到**只监听 `127.0.0.1` 的服务**——所以桥接**不需要改绑 `0.0.0.0`**。

实测命令（设备侧）：
```
printf "GET /agent-api/health HTTP/1.0\r\nHost: 10.0.2.2\r\n\r\n" | toybox nc -q 3 10.0.2.2 8788
→ {"ok":true,"sessions":21,"voice":{"asr":true,"tts":true,"maxSeconds":60}}
```

### 又一个"只有换环境才暴露"的 bug：`NetworkOnMainThreadException`

App 连本机 HTTP 时一切正常，**换成公网 HTTPS 立刻炸**：

```
android.os.NetworkOnMainThreadException
  at com.android.org.conscrypt.ConscryptEngineSocket$SSLOutputStream.writeInternal
  at okhttp3.internal.connection.RealConnectionPool.evictAll
  at cn.waveflow.luckycat.contract.AgentApi.close(AgentApi.kt:192)
```

`AgentApi.close()` 里 `connectionPool.evictAll()` 会去关连接池里的连接，
而 **HTTPS 连接在关闭时 Conscrypt 要写出 `close_notify`——那是一次真实的网络写**，
被 Android 的 StrictMode 拦下。明文 HTTP 不触发，所以只连本地开发环境**永远看不出来**。

修法：`close()` 改成 `suspend`，内部 `withContext(Dispatchers.IO)`。
调用方（本来就都在协程里）不必各自记得"close 要放后台"。

### 一条约定，以及为它加的断言

`AgentApi` 的 `baseUrl` 是**主机根**（`https://bank.waveflow.cn`），
`/agent-api` 前缀由它自己拼。这个约定没写清时踩了一次：传了带前缀的地址，
拼成 `/agent-api/agent-api/health`，服务端回 404，**报错看着像路径写错、其实是约定搞混**。

所以加了构造期 `require`：带了路径就直接抛，并在信息里说清该传什么。
配一条测试（`baseUrl 带了 agent-api 前缀要在构造时就报错`）钉住。

### 新增 `:domain` 模块（纯 JVM）

界面之外的真逻辑（登录规则、会话存档形状、挑战展示模型）放这里，
`./gradlew :domain:test` 不需要模拟器就能跑——和网页版那批离线 `check-*.mjs` 一个意思。
`:contract` 保持"只描述桥接接口面"，不掺业务。

登录规则**逐条照抄网页版**（`app/src/api/mock/index.ts`），包括两个容易漏的细节：
- 校验次序是**先密码、后验证码**（反过来会让"验证码错误"被用来反推手机号是否存在）；
- `login` 与 `sendSmsCode` 用的是**两个不同的手机号正则**（严格 `1[3-9]\d{9}` vs 宽松 `\d{11}`）——
  这不是笔误，照抄是为了不制造第三种行为。

### 修正：Room → DataStore

原计划用 Room 存会话历史。看完 `agentSessions.ts` 的实际规模（上限 50 段对话 /
单条 2 万字 / 总共 2MB）之后改成 **DataStore + kotlinx.serialization**：
这点数据量换不来 Room 的 KSP、代码生成和迁移。版本目录里 Room 仍然登记着，
真需要关系查询时再上。

## 银行数据从哪来：占位后端（已解决）

安卓要显示账户、流水、理财、卡片这些页面就得有数据，而数据原本只是网页版里的
一个前端 mock。"给安卓再抄一份 Kotlin 版"会必然与网页版漂开，所以做的是一条
**占位后端**：把那份前端 mock 直接挂到服务器上，路径由
`app/src/api/contract.ts` 的 `routes` 定义（`/api/*`）。

```
安卓 App ──► https://bank.waveflow.cn/api/… ──► nginx ──► luckycat-bridge
                                                            └─ import app/src/api/mock
```

对安卓来说这就是"一个普通的 HTTP 后端"：`:contract` 里那套 OkHttp + JSON 照用，
只需要再补一层 `/api/*` 的客户端与类型。真后端上线时换 baseUrl 即可。

实现、踩到的两个坑、以及"用现有那批浏览器门禁去打它"的验证结果，
见 `P15-DEMO-BANK.md`。**网页版暂时仍走自己的前端 mock**（纯静态、可离线），
只有安卓端用占位后端。

### 又踩了一次嵌套注释（这次有机械检查兜住）

PhoneRules、LoginViewModel），所以 `android/scripts/gate.sh` 里加了一条纯 grep 的
静态检查，不靠记性。

**几个刻意的设计**：

- 详情页的**对账提示是真的会报异常的**：`交易前余额 + 交易金额 ≠ 交易后余额` 时
  显示一行警告，而不是把两个数并排一放就完事。
- 追加分页失败时**不清空已有列表**：用户已经看到的东西不能因为翻页失败就消失。
- ViewModel 按 id 给 key（`viewModel(key = "account-$id")`）：不给的话从 A 账户
  进 B 账户会复用前一个 ViewModel，显示 A 的流水。

### `:domain` 里现在有什么

| 文件 | 干什么 | 用例数 |
| --- | --- | --- |
| `Money` | 金额/利率格式化，逐条照抄 `format.ts` | 12 |
| `PhoneRules` | 按钮什么时候能点（正则与后端一致） | 6 |
| `Dates` | 时间显示，**容错解析**三种 ISO 形态 | 8 |
| `Labels` | 枚举 → 中文，逐条照抄 `categories.ts` / `tx.ts` | 4 |
| `TransactionFields` | 详情的字段拼装与对账判定 | 8 |

`Labels` 里**刻意没有** `account.kind → 中文` 的映射：网页版也没有这张表，
账户显示名由后端在 `Account.label` 里直接给。我一开始照着 kind 猜了一张
（还顺手加了 mock 里根本不存在的 `time`），那是**自己发明业务语义**——
后端加一个类型客户端就得跟着改，改错了还没人报错。

### 静态检查自己也被修了一次

那条"嵌套注释"检查第一版写成"任何非 KDoc 的 `/*`"，结果**误报**了
`Labels.kt` 里一个完全正常的块注释。收紧成"注释续行（行首是 `*`）里出现 `/*`"

### 客服聊天 + 两张卡片（已跑通）

这是「交易/敏感信息：先展示 → 用户确认 → 身份验证 → 才执行」这条硬要求在安卓端的落点。
真的走通了：模拟器发一句 `hello`，**真 agent** 回了
「您好，我是招财猫银行的智能客服小招。请问有什么可以帮您？」

**分层**（规则都在 `:domain`，界面只负责画）：

| 规则 | 在哪 | 为什么放这 |
| --- | --- | --- |
| 过没过期、要不要密码、能不能提交 | `ConsentPresentation` | 算错就是安全问题，必须能离线测 |
| 每题必答、单选不能多选 | `QuestionAnswers` | 违反了后端回 400，界面只表现为"点了没反应" |
| 工具结果摘要 | `ToolSummary` | 一堆分支，每条只影响一行字，肉眼很难发现退化 |
| 对话存档（标题、裁剪、体积） | `Conversations` | 上限与丢弃策略是可以离线验的确定性规则 |

**几条刻意的设计**：

- **确认卡片不能被"收起来"**：密码错（401）时桥接**不结算**挑战，所以卡片留着、
  只清空密码框。收起卡片等于把用户唯一的机会关掉，而 agent 那边还在等。
- **语音不能确认**：`ChatViewModel` 里没有任何"用语音答确认"的入口，
  `answerConsent` 只被卡片上的按钮调用。
- **过期的挑战两个按钮都点不动**，并显示"已超时"而不是"0 秒内有效"。
- **会话 id 懒创建**：没发过话的对话在服务端不留空会话。

### 三个只会在设备上出现的问题（都修了）

1. **确认卡片被输入法顶到屏幕外**。输入框获得焦点后系统把**整个窗口平移**了
   851px，新出现的确认卡片跑到屏幕上方——**用户根本看不到要核对的信息**。
   修法是给聊天页加 `imePadding()`，让这一屏自己收缩而不是让系统去平移窗口。
   *这条是 instrumented 测试抓出来的：节点存在，但 `assertIsDisplayed` 失败。*
2. **取消被当成失败**（又一次）。`subscribe()` 里 `catch (e: Exception)` 会把
   `CancellationException` 一起吞掉，于是切标签页/换会话时界面冒一条"网络不给力"。
   修法是先 `catch (e: CancellationException) { throw e }`。
   这与 `:contract` 里那条"取消 ≠ 失败"是同一类错误，只是层次不同。
3. **`assertTextContains` 的 `substring` 默认是 false**（要求整串相等），
   所以"已超时，请让助手重新发起"不匹配"已超时"。测试自己踩的坑。

### 嵌套注释：从"记得跑检查"改成"不跑就编译不过"

这个错本轮又犯了两次（`AppGraph` 与门禁脚本自己的 KDoc），累计六次。
之前它只是 `gate.sh` 里的一条 grep——而那要人**记得先跑**，实际发生的几次
全是"写完直接 build"。现在挂成了 Gradle 任务 `checkNestedComments`，
任何 Kotlin 编译之前先跑，报错直说"注释里嵌套了块注释"而不是
Kotlin 那句指向文件末尾的 "Unclosed comment"。

**顺手把它自己绊了一次**：我在根 `build.gradle.kts` 的注释里写了带 `/*` 的路径，
`.kts` 也是 Kotlin，块注释同样嵌套，于是**后面注册任务的代码全被注释掉了**。

### 会话历史（本轮）

聊天页右上角「历史」→ 覆盖层列出聊过的对话（标题、条数、相对时间），点一条切回去。
用**自己画的覆盖层**而不是 `ModalBottomSheet`：后者还带 `@ExperimentalMaterial3Api`，
而这里要的东西（一层遮罩 + 一个列表）自己写更短，也不用跟着实验 API 的签名变。

写这段时又抓到两个真 bug：

1. **存档为空时的第一段对话永远不会进历史**。`init` 只在列表非空时取第一个，
   而 `update()` 用的是 `conversations.map { ... }`——空列表映射完还是空。
   于是用户聊了半天，在历史里找不到它。修成 **upsert**（列表里没有就补进去）。
2. **测试之间互相污染**。`ConversationStore` 落在应用私有目录，而 instrumented
   测试共用同一个安装——后一个用例读到了前一个留下的对话，断言变成看运气。
   （症状很有迷惑性：`会话是发第一句话时才建的` 拿到了上一轮的 `agentSessionId`。）
   修法是每个用例 `@Before` 先删存档文件。

### 一条盯"取消不是失败"的回归测试

上一轮发现 `subscribe()` 的 `catch (e: Exception)` 会把 `CancellationException`
一起吞掉（切标签页冒假错误），但那只是口头结论。这轮补了测试：让 MockWebServer
用 `SocketPolicy.KEEP_OPEN` **保持 SSE 连接开着**，这样取消才真的发生在一次
阻塞读取上（有限 body 会立刻 EOF，取消路径根本走不到），然后断言 `error == null`。


### 转账：先把"接口面"钉住（界面下一轮）

这一轮顺手把转账的类型与客户端方法加进了 `:contract`：
`Payee` / `TransferQuote` / `TransferRequest` / `TransferResult`，以及
`listPayees` / `quoteTransfer` / `submitTransfer`。

**字段是照着后端真实返回写的，不是照 TS 类型抄的**——先 `curl` 看了
`/api/payees` 与 `/api/transfers/quote` 的实际形状再定。差别不小：真实的
收款人带 `scope` 与 `fpsMethod`，而 TS 类型里这两个是分散在几个联合类型里的。

`Payee` 的注释里留了一条业务约束：**`bankCode` 与 `bankRegion` 必须成对使用**
——3 位清算代码两地会撞号（004 在香港是汇丰、在内地是另一家），只带一个会转错行。

另外补了 `Money.parseToCents`（用户输入的元 → 分），配 10 条测试。
金额解析是最容易出错的一环，所以写得很细：超过两位小数**判为无效而不是四舍五入**
（静默把 `800.555` 变成 `800.56` 是在替用户改金额）；用 `BigDecimal` 而不是
`toDouble() * 100`（后者在 `8.7` 上会给出 869.9999…，取整少一分钱）；
千分位逗号、全角数字、`元` 后缀都要认。


### 转账页（本轮）

顺序是刻意的：**选账户 → 选收款人 → 填金额 → 报价 → 提交**。
报价那一步不能省：手续费、到账时间、单笔上限都要用户先看到，
点了确认之后才发现扣了手续费是最典型的投诉来源。

**一条安全规则：任何输入变动都让报价失效**（`TransferViewModel.invalidateQuote`）。
报价里带着手续费与**单笔上限**，用户报完价再改金额，如果还留着旧报价，
界面会显示"手续费 0 元、上限 5 万"而金额已经变成 8 万——用户按着那组过期的数字
点确认，看到的和实际要发生的就不是一回事了。换账户、换收款人、改金额、改附言
四条路径都会清掉它，其中三条有 instrumented 测试盯着。

`TransferDraft`（拼转账请求）放在 `:domain`，因为有两条**会转错钱的约束**
在界面上看不出来：

1. **`bankCode` 与 `bankRegion` 必须成对下发**。3 位清算代码两地会撞号
   （004 在香港是汇丰、在内地是另一家），只带一个就可能路由到错误的银行。
   所以要么两个都给、要么两个都不给——测试里专门有一条造了"只有一个"的收款人。
2. **`fps` 通道才带 `fpsId`**。银行通道带上会让后端多一层判断，语义上也不该有。

字段是**照着后端真实返回写的**（先 `curl` 看了 `/api/payees` 与
`/api/transfers/quote`），不是照 TS 类型抄的。

模拟器上验过：账户与收款人都来自公网后端（5 个收款人带"转数快 xxx"/
"银行 尾号 xxxx"两种标识），三样没填齐时"查看报价"按钮确实点不动。

**还没做的**：`requiresConfirm`（风控二次确认）在界面上只是显示一行字，
没有走"再确认一次"的流程——真接上后端时要补。


### 卡片页（本轮）

列表（卡面、网络、尾号、状态、单日限额）+ 锁卡 + 网上支付/境外支付两个开关 +
**查看卡密**。模拟器上验过：真实后端返回三张卡，其中一张是「已锁定」。

三条刻意的设计：

1. **列表接口不下发完整卡号**。`BankCard` 里没有 `cardNo`、没有 `cvv`——要看卡密
   得单独调 `revealCardSecrets` 并且**必须带支付密码**。拿得到列表的人不该顺手
   拿到能盗刷的东西。
2. **卡密只放在内存里**。查出来挂在 `CardsUiState` 上，关掉弹窗或离开页面就没了
   （`onCleared` 里也显式丢掉）。演示环境返回的是占位值（界面上明说），
   但真后端会返回真卡号——不落盘这条从现在就得守住。
3. **密码错时弹窗留着、只清空输入框**。关掉的话用户得重新点一次"查看卡密"，
   还会以为功能坏了。与确认卡片同一条规矩。

改卡设置用的是 **PATCH 而不是 POST**——部分更新，只传 `onlinePayment` 不该把
`dailyLimit` 一起重置掉。契约测试里有一条专门断言"没传的字段不出现在请求体里"。

「我的」这一轮做成了真的入口枢纽（用户信息 + 银行卡入口 + 退出），
不再是占位页——底栏只有五个位置，银行卡、安全中心、分析、开户都该从它进。


### 理财页（本轮）

总览（总市值 / 累计收益 / 昨日收益）+ 持仓 + 在售产品。模拟器上验过真实数据。

**这一页只做"看"**：申购与赎回**没做**。那条链路要过适当性匹配（投资者等级 vs
产品风险）、抄录风险确认语句、再输支付密码，是个独立的合规流程，
不适合塞进"看完就能点"的页面里凑数。

三条与合规有关的显示规则（改代码时别动）：

1. **业绩比较基准渲染成区间**（`1.60% ~ 2.10%`），不挑一个数字当"收益率"——
   它不是承诺收益。后端给 `kind`/`low`/`high` 三个字段就是为这件事。
2. **不保本要显眼**。字面是「不保本」三个字，配强调色。
3. **理财账户没开立时明确提示**，而不是让用户点了申购才发现走不通。

风险等级用**通俗说法**（「低风险」）而不是只给 `R1`——这是新规要求，
网页版 `RISK_PLAIN_LABEL` 的注释里也写着。`C`（投资者）与 `R`（产品）
是两套，测试里专门有一条防止把 `C1` 映射成 `R1`。

#### 一个只有跑起来才会发现的显示 bug

`"**不保本**"` —— 我按 Markdown 的习惯写了强调，**但 Compose 不解析 Markdown**，
界面上原样显示成 `**不保本**`。原测试写的是
`assertTextContains("不保本", substring = true)`，所以它**照样通过**——
星号在不在它都不管。改成 `assertTextEquals("不保本")` 之后才有了牙齿，
并做了变异验证（把星号放回去 → 红，还原 → 绿）。

强调靠颜色与位置做，不靠 Markdown 记号。


### 安全中心（本轮）

评分 + 身份验证状态 + 风控规则（4 条，可开关）+ 登录设备 + 安全日志。
模拟器上验过真实数据。

**一条刻意的设计**：每条规则都把"它在拦什么"**完整显示**出来，不省略。
「境外交易拦截」这五个字看不出它到底拦什么，而用户正是在这里决定要不要
关掉自己的保护——描述被截断等于剥夺了他判断的依据。

**不做乐观更新**：`setSecurityRule` 返回整个总览，界面直接换掉。
失败时只显示错误、开关**保持原状**——安全设置上最坏的一种不同步是
"界面说关了、后端其实没关"。instrumented 测试里有一条专门让后端返回 500
来盯这件事。

改密码、换手机号这类**真正动安全设置**的操作没放进这一页：
它们必须走独立的身份验证链路，塞进来凑数比不做更糟。


### 财务分析 + 开户（本轮）

**分析**：本月支出构成（带占比条）、六个月趋势、近 30 天现金流。
一条刻意的实现选择：**占比直接用后端给的 `ratio`，不自己拿 amount 除总数**——
两边的分母口径必须一致（后端可能按"已分类支出"算，而总数含未分类），
自己算会出现"各项加起来 103%"这种解释不清的画面。测试里用
"后端给 0.53、自己算也是 53%"这种**险过**的数据钉住它（口径一旦不同就红了）。

**开户**：三类户的功能与限额 + 短信验证。模拟器上验过真实数据——
Ⅰ 类户那一张卡片上直接写着后端给的 `offlineReason`：
「按账户分类管理规定，Ⅰ 类户需本人持身份证到柜台面签，无法在线开立」。

三条来自后端的硬约束，界面都要能看出来：

1. **不能在线开的类别连点都点不动**（`clickable(enabled = tier.online)`），
   而且原因写在卡片上。让用户点进去才被拒是更糟的体验。
2. **必须过短信验证**——验证码先调 `/api/auth/sms-code`，演示环境会回传并自动填上。
3. 验证码一次性（后端行为）。

**没做**的是"真正的开户"里更靠后的部分：协议签署、地址、支付密码。
演示后端没有那几步，硬凑会变成假的流程。

#### 两个测试自己踩的坑

- **`clickable` 会合并子节点**（`mergeDescendants`），卡片里的说明文字在合并树里
  找不到，得用 `onNodeWithTag(..., useUnmergedTree = true)`。
- 我把一条断言**写反了**：验证码自动填上之后表单就齐了，按钮**应该**变成可点，
  而我断言了"不可点"（那是没填码时的状态）。


### 语音（本轮）

两半都做了：

**流式朗读**——`AudioTrack` 逐帧写裸 PCM16，**首帧到达就出声**，不等整段合成完。
网页版那套 Web Audio 的自动播放策略（`playBlocked`、用户手势解锁）在安卓上不存在，
所以这边简单得多。

**按住说话**——`MediaRecorder`（MPEG_4 + AAC）→ 裸 base64 → `/agent-api/asr` → 转出来的话**直接发出去**。
用**按住**而不是"点一下开始、再点一下停"：后者会让用户忘了停、麦克风一直开着，
而 P8 里"只有按着的时候才录"那条是有意的。

#### 网页版踩过的三个坑，一个没落

1. **取消 ≠ 失败**。网页版的 bug 是 `teardownPlayback()` 先 abort 了 controller，
   之后再读 `signal.aborted` 永远是 true——**真失败被吞掉**。
   这里在拆之前先把 `wasAborted` 记下来。
2. **"播完了"要三段一起判**：不再有新帧 + 播放头追上写入量 + 确实写过东西。
   网页版只按"排到哪儿了"判断，结果第一帧播完就报了结束。
3. **波形在整段合成完之后才算**。边收边算会把尾巴丢掉，而且波形会在播放过程中
   不断变化，看着像坏了。

#### 分层的理由（能离线测的都下沉了）

| 逻辑 | 在哪 | 为什么 |
| --- | --- | --- |
| PCM16 小端解码 | `:domain` `Pcm` | 字节序写反了听到的是噪声，界面上**什么错都不报** |
| 波形包络（分桶/峰值/归一化） | `:domain` `Waveform` | 与网页版同一个切法：纯函数那一半单独验 |
| Markdown → 可朗读文本 | `:domain` `SpeechText` | 表格、链接、代码块一堆分支，每条只影响听感 |
| 字节流播放 | `:app` `PcmPlayer` | 只有它需要 `AudioTrack` |
| 录音 | `:app` `VoiceRecorder` | 只有它需要 `MediaRecorder` |

#### ⚠️ 这一块**没有被完全验证**

instrumented 测试验的是**接线**：点朗读真的去请求了语音流、录音按钮在、

### Markdown 渲染（本轮）

解析放在 `:domain`（`Markdown`），渲染在 `app`（`MarkdownText`）。

**三条安全选择，与网页版一致**——输入是模型产出，不能当可信内容：

1. **不解析 HTML**：`<b>` 之类原样当文字，不变成结构。
2. **图片不渲染**：Markdown 图片会把 URL 变成一次自动请求——那是"把对话内容
   编码进请求地址外带"的经典通道，也能当追踪像素。这里退化成一行提示。
3. **链接只认 `http`/`https`/`mailto`**：`javascript:`、`data:`、`file:` 原样显示成文字。
   协议判断**大小写不敏感**（`JavaScript:` 一样危险）。

这三条在界面上看不出对错，所以测试是拿**恶意输入**喂进去验的。

**明确不支持的**：KaTeX 公式。网页版会真的排版出来，这里原样显示 `$…$`。
排公式要引入整套 LaTeX 排版器，不是"顺手支持一下"。

#### 解析器写出了一个死循环

第一版测试**跑挂了 10 分钟**才被超时杀掉。原因：一行以 `|` 开头但**不是**合法表格时，
`parseTable` 返回 null 落到段落循环，而段落循环的 break 条件里又有「以 `|` 开头」
——两边都不吃这行，`i` 不前进。

修法是让两处用**同一个判断**（`isTableStart`：以 `|` 开头**且下一行是分隔行**），
并在段落为空时兜底 `i += 1`。教训是：**循环里的"break 条件"与"处理条件"必须是同一套**。

### 一个找了三次的假错误：SSE 被自己的读超时掐断

从第 2 轮起，界面上就时不时冒一条「网络不给力」——**回复明明已经收到了**，
十几秒之后才冒出来。前两次我都当成"取消被当成失败"处理（那也确实是一个真 bug），
但这次顺着 logcat 拿到了真凶：

```
java.net.SocketTimeoutException: timeout
  at okio.RealBufferedSource.readUtf8Line
  at cn.waveflow.luckycat.contract.AgentApi$streamEvents$1$reader$1
```

**OkHttp 默认读超时是 10 秒，而桥接每 15 秒才发一次 `: ping` 保活**——
每条 SSE 订阅都会在空闲 10 秒后被自己掐断。

修法是给流式请求单独一个客户端，读超时放到 60 秒（大于心跳间隔，又能在真断了
的时候一分钟内发现）。契约测试里加了一条断言把"必须大于 15000ms"钉住。

模拟器上验过：发一句、**等 45 秒**（远超原来那个 10 秒的点），界面上不再冒假错误，
logcat 里中断次数为 0。


### 发图（本轮）

从系统相册选图 → 校验 → 压缩 → 带图发消息 → 界面上显示缩略图。

#### 两层上限，别混（桥接侧也是这么分的）

| 层 | 值 | 作用 |
| --- | --- | --- |
| **来源**上限 | 20MB | 相册里的原图。**不拦**——一张 20MB 的图是正常的，压缩之后才发 |
| **策略**上限 | 6MB | 与服务端一致。超了服务端回 413，所以发之前就要拦住 |
| 长边 | 1600px | 压缩目标 |
| 缩略图长边 | 160px | 存进对话存档的那份 |

#### 为什么必须两份图

发给 agent 的要够清楚（1600px），而**存进本地存档的必须很小**：
存档总预算只有 2MB，原图一张就能吃掉一大半。网页版 `lib/image.ts` 也是这么分的。

#### 三个刻意的实现选择

1. **用系统相册选择器**（`PickVisualMedia`），不是"申请读整个相册的权限"。
   用户只交出他选中的那一张——这是权限上更小的口子。
2. **先只读尺寸再解码**（`inJustDecodeBounds` + `inSampleSize`）。
   直接解一张几十 MB 的原图会 OOM。
3. **压缩后统一成 jpeg**。PNG 截图压不下去，一张就能撑破 6MB。

#### 测试覆盖到哪、没覆盖到哪

- **覆盖了**：消息体里 `image` 字段的形状（裸 base64、mimeType）、
  只有图没有文字也能发、界面上缩略图出来了、**真图会被压到 1600px 以内且小于 6MB**。
- **没覆盖**：`ImagePreparer` 的**相册选择器那一段**（`PickVisualMedia` 是另一个应用，
  测不了）。它是 `ImagePreparer` 的**调用方**，所以 `prepare()` 本身是被真图测过的，
  只有"点了按钮弹出系统选择器"这一步要人工走查。


### 消息动作（本轮）

「重新生成」与「编辑重发」。逻辑放在 `:domain` 的 `Conversations`
（`lastAssistantId` / `promptOf` / `rewindTo`），与网页版逐条对齐。

**两条刻意的规矩**：

1. **「重新生成」只挂在最后一条助手回复上**。挂到中间那条，重新生成就得把它
   **后面**的几轮问答全丢掉——用户点的是"重说这一句"，代价却是删掉后面十分钟
   的对话。测试里专门断言中间那条**没有**这个按钮。
2. **助手回复要换算回产生它的那句提问**。按钮挂在助手回复上，但倒回要倒到提问——
   这个换算漏了就是**静默失灵**：拿着助手 id 去 `rewindTo` 被规矩拒掉，
   于是点了什么都不发生。

**重发不会再追加一条用户消息**：倒回之后那句已经在列表里了，再追加就是重复。
instrumented 测试里有一条专门断言"发完之后用户消息仍然是两条"。

界面上的编辑弹窗里写明了那条容易被忽略的事实：**助手那边的会话记录退不回去**，
所以这是"在同一个上下文里再问一遍"，不是"回到当初那个状态"。

#### 这一轮测试自己踩了三个坑

1. **在 `init` 完成前就 `send`**——读存档是异步的，那之前 `conversation` 是 null，
   `send` 直接返回。走界面点按钮的用例碰不到（`LaunchedEffect` 已经加载好了）。
2. **助手事件可能比 202 回执先到**，那时 `sending` 还是 true，下一次 `send` 被
   "发送中"挡掉——那是**预期行为**（按钮这时是灰的），是测试没等它落下来。
3. **mock 的 SSE 只有一个 assistant 事件**，所以"发两轮"的第二轮永远等不到回复
   （真实桥接是长连接、每轮推一条）。最后改成**直接种一段两轮对话的存档**——
   更确定，而且这几个用例要测的本来就是"对已有消息做动作"。

### 真桥接那一层抓到一个真 bug（离线抓不到）

`LiveContractTest.事件流第一帧是 hello` 一跑就红：

```
java.net.SocketException: Socket closed
  at okhttp3.internal.http1.Http1ExchangeCodec$ChunkedSource.readChunkSize
  at LiveContractTest$事件流第一帧是 hello$1$first$1.invokeSuspend(LiveContractTest.kt:72)
```

原因是**取消被当成了失败**：界面订阅事件流后常常只要前几帧就取消
（`first()` 就是这个形状），取消触发 `awaitClose` 里的 `call.cancel()`，
阻塞中的读取于是抛 `SocketException: Socket closed`，而它被当成错误往收集方报了。
用户按"停止"就会看到一条报错。

修法是判据用 `isActive`：**取消导致的 IOException 吞掉，真失败照旧上报**。
和 web 端那个坑正好是反面——那边是 `teardownPlayback()` 先 abort 再读
`signal.aborted`，把**真失败**吞掉了。

### 一条空断言，以及为什么离线抓不到它

修完以后我按纪律做了变异验证（把 `isActive` 改回"一律上报"），
结果**离线那两条"取消不抛异常"照样绿**——它们是空断言。

原因是时序：`first()` 拿到值就取消了收集，reader 随后抛的异常被送进一个
**已经没人读的 channel**，静默丢掉，观测不到。试过 `SocketPolicy.KEEP_OPEN`
想让读取真的阻塞住，也不行，同一个原因。

真桥接那条则稳定抓到：变异版**连跑 3 次全红**。所以：

- **取消竞态的唯一有效守卫是真桥接那条**（已在测试文件里写明，别删了当成冗余）；
- 离线那两条保留，但注释里明确写了"这条不覆盖那个 bug"，只值"浅层不崩"这一点；
- 反向那条（`流到一半被掐断要抛出来`）是确定性的，也做了变异验证：
  把 IOException 一律吞掉，它立刻红。

## 第 16 轮：真机走查抓到的两件事

第一次把 Debug 包装到**真机**（荣耀 `AMG-AN00` / Android 16 / 1200×2664 @520dpi）上跑，
一上来就看到会话里一直没发现的问题。

### 1. 系统栏压住内容（已修）

用户第一眼就指出来：「通知栏都和文字重叠了」。实测数字：

| 量 | 值 |
| --- | --- |
| 状态栏 inset frame | `[0,0][1200,126]` → **126px（38.8dp）** |
| 导航栏 inset frame | `[0,2592][1200,2664]` → 72px |
| App 窗口 frame | `[0,0][1200,2664]`，`statusBarColor=#0` → 整窗铺满 |
| 「招财猫银行」标题 bounds | top = **78px** |

**标题顶端 78px 落在 126px 的状态栏里，被压进去 48px。**

根因不是"某屏少写了 padding"，而是 targetSdk 36 → Android 15+ **强制 edge-to-edge**
（`decorFitsSystemWindows` 被强制 false），而全项目**一处 `WindowInsets` 都没消费**：

```
grep -rn "enableEdgeToEdge|WindowInsets|systemBars|safeDrawing|statusBar" app/src → 0 命中
```

`themes.xml` 里那句「这里只负责窗口本身（状态栏、背景）」是**当时的假设，在 API 36 上不成立了**。

**为什么在根部一次消费，而不是逐屏加：**

`AppShell` 那条路有 `Scaffold` 兜底，真正裸奔的是 **shell 外面的登录页与开户页**
（`LuckyCatRoot` 直接渲染）。逐屏补的代价是"以后每加一个 shell 外的屏再踩一次"。
所以改成在 `onCreate` 里包一层：

```kotlin
enableEdgeToEdge()                                   // 顺带解决深浅图标
Box(Modifier.fillMaxSize().windowInsetsPadding(WindowInsets.systemBars)) { LuckyCatRoot(graph) }
```

- 根部消费后 `Scaffold` 拿到的 inset 归零，**不会重复加一份**；
- 用 `systemBars` 而**不是** `safeDrawing`：后者含 IME，在根部吃掉键盘 inset 后
  客服页自己的 `imePadding()` 会变空操作，消息列表的收缩行为也跟着变。

修后真机实测：标题 top **78px → 204px**（126 状态栏 + 24dp 页面内边距 = 204，正好）。

### 一条盯这个不变量的门禁（含变异验证）

新增 `EdgeToEdgeInsetsTest`（`createAndroidComposeRule<MainActivity>()`，未登录即登录页）。
断言基准取**设备自己报的 inset**，不写死 dp——各机型状态栏高度不同（这台 38.8dp，
模拟器 128px），写死数字会在别的设备上假红/假绿。

`statusTop > 0` 是**显式的空断言防线**：取不到 inset 就直接红，不许安静通过
（本项目已经栽过两次空断言）。

变异验证：把根部那行 `windowInsetsPadding` 去掉 → 立刻红：

```
java.lang.AssertionError: 标题顶端 63.0px 落在状态栏 128px 里面（内容被压住了）
```

恢复后绿。全量 instrumented 82 条（81 原有 + 1 新增）通过，`gate.sh` 三层全过。

> 顺带纠正上一轮的说法：会话里写的「模拟器截图确认」在这点上是**不成立的**。
> 模拟器也是 API 35+，同样强制 edge-to-edge，只是当时没盯着系统栏看。

### 2. 线上的占位后端是旧的（**尚未修**）

登录之后首页显示的还是**三账户**——「活期账户 ¥128,640.55」「储蓄账户 ¥56,000.00」。
本地桥接与公网打出来的对比：

| --- | --- |
| 本地桥接（仓库现状） | `acc_0001 kind=savings 储蓄账户 余额=28464055 可用=28464055`，无 `tier` |
| 公网 `bank.waveflow.cn` | `acc_0001 活期账户 / acc_0002 储蓄账户 / acc_0003 定期存款`，带 `tier` |

**「统一储蓄账户」那一轮只改了仓库，没重新部署。**安卓真机连的是公网那份
（`AGENT_BASE` 默认 `https://bank.waveflow.cn`），所以看到的仍是旧模型。

按 `P15-DEMO-BANK.md`，线上桥接是**运行时** import `app/src/api/mock/index.ts`

## 第 17 轮：图标从 Canvas/emoji 换到矢量资源

用户在真机上指出客服输入栏那两个图标「很突兀」——**那不是图标，是彩色 emoji**：

```
ChatScreen.kt:265   "🖼"  选图按钮，style = titleMedium(17sp)
ChatScreen.kt:292   "🎤"  按住说话，style = headlineSmall(26sp Bold)
```

系统 emoji 字体渲染：彩色、字面体量跟字号走、不吃品牌色。而全站图标本来只有一套
语言（`theme/NavIcons.kt` 里 Canvas 画的圆头描边、由 `Palette` 上色），
中间混进一个 emoji，一眼就不对。尤其那个话筒是 26sp 粗体，比「发送」还抢眼。

### 全项目扫了一遍，会渲染给用户的只有 4 处

| 位置 | 字符 | 处置 |
| --- | --- | --- |
| `ChatScreen.kt:265` | U+1F5BC | **替换**成矢量图标 `ic_image` |
| `ChatScreen.kt:292` | U+1F3A4 | **替换**成矢量图标 `ic_mic` |
| `TransactionScreen.kt:113` | U+26A0 U+FE0F | **删掉**，警示改由 `color` 表达 |
| `TransferScreen.kt:302`、`WealthOpeningScreen.kt:120/242` | U+2713 `✓` | **保留** |

`✓` 不是彩色 emoji：没有 `FE0F`、不被 emoji 字体接管、受 `color` 控制，
属于排版符号，本来就是有意用的。

其余命中全在**注释、测试夹具、设计文档、脚本 CLI 输出**里（`rag.test.mjs` 里那个
`'💳'.repeat(10)` 是刻意的 4 字节样本），不渲染给用户，一律没动。
网页侧用户可见 emoji 是 **0 处**（`app/src` 那几处都在注释里），所以这轮只动安卓。

### 矢量资源是安卓的 SVG 等价物

真 `.svg` 要引 `coil-svg` / `androidsvg` 做运行时解析，多依赖多开销；
`res/drawable/ic_*.xml` 的 `pathData` **就是 SVG 的路径语法**，
Android Studio 的「Vector Asset」导 SVG 也是转成它。九个图标：

```
ic_home ic_transfer ic_support ic_wealth ic_profile ic_card    ← 原有 6 个，形状逐点平移
ic_image ic_mic ic_send                                        ← 新增 3 个
```

- **6 个老图标形状没变**：原来的坐标是 `w * 0.10f` 这类比例，乘 24 就是 24 格里的绝对值；
  线宽原来写 `size * 0.11f`（22dp 下 2.42dp），所以资源里写 `strokeWidth="2.64"`
  （`2.64 * 22 / 24 = 2.42`），粗细一致。
- **`NavGlyph` 名字与签名没变**，内部从 `Canvas` 换成
  `Image(painterResource(...), colorFilter = ColorFilter.tint(color))`；
  枚举加 `@DrawableRes val res`。所以 `HomeScreen` / `AppShell` 的调用点**一行都没改**。
- 三个圆形控件统一 **44dp**；录音中话筒换成实心主色 + 白色图形（与底栏选中态同一语言）；
  输入框从 `OutlinedTextField` 描边换成填充式 24dp 圆角（与全站卡片同一语言）。
- 顺手补了无障碍：三个图标各自 `contentDescription`（"选择图片"/"按住说话"/"发送"）。
  不补的话，原来那个 emoji 文本还能被读屏念出来，换成 `Image` 之后就变成"没名字的按钮"。

### 两个坑，各配一条门禁（都做了变异验证）

**① `fillColor` 忘了写透明 → 图标变成一块实心方块。**
`ColorFilter.tint` 是 SRC_IN：**所有非透明像素**会被整片染成主色。
这条**编译期查不出来**，只有上了真机才发现图标是个方坨。

**② 界面上再混进 emoji。** 静态检查拦在 `gate.sh` 里：

```
== 静态检查：矢量图标必须是描边（透明填充） ==    ← 每条 path 的 fillColor 必须是 #00000000
== 静态检查：界面代码里不许有 emoji ==            ← 扫 src/main 的 .kt
```

emoji 那条只扫 `app/src/main` 的 Kotlin（那是"会不会渲染给用户"的分界线），
dingbat 段用负向先行断言把 `U+2713`/`U+2714` 剔掉——不剔的话选择态那三处 `✓` 会误报。
这条**不完备**（`✓`、`›`、`·` 这类文本符号与后端来的正文都不在范围内），已写在脚本注释里。

> 写这条门禁时它当场抓到了我在 `ChatScreen` 注释里留的一个 emoji——变异验证之前先自证了一次。

**为什么"透明填充"这条是静态检查，而不是像素测试？** 量过：描边形态下覆盖率最高的
`ic_image` 是 **0.395**，而把 `ic_home` 的 `fillColor` 改成实色后是 **0.544**——
看着能分开，但话筒那种小形状填实之后的覆盖率可能**更低**，一个全局阈值不是漏判就是误判。
透明度是资源里的静态事实，用静态检查表达它更诚实。（这条是变异验证时发现的：
第一版把两条都塞进像素测试，改实色**它照样绿**。）

像素测试（`IconVectorTest`）只留两件它擅长的：**画得出内容**（占比 > 2%，
抓 `pathData` 写错导致空白）和**吃得上品牌色**（用 SRC_IN 染成 `Palette.accentDeep`
后平均 RGB 必须等于 `#9C7226`，抓资源写死颜色）。

### 第 17 轮修订：输入栏药丸化（走查复盘）

矢量版上机后人眼走查，发现三个测试抓不到的视觉问题：

1. **三个按钮的圆形底"没了"**。attach/mic 垫的是 `Palette.accentTint`（浅米黄），
   和页面 `bg`（米黄）色差太小，圆形底几乎不可见，图标像直接贴在背景上；
   发送按钮的灰底也偏弱。像素测试**不可能抓这个**——它测的是"画得出内容/吃得上 tint"，
   两个都成立，但"对比度够不够、成不成一块"是视觉判断。
2. **输入框和按钮没对齐**：TextField 56dp，按钮 44dp，`Alignment.Bottom`
   底部齐平、顶部冒 12dp。
3. **「新对话」出现两次**：空态副标题默认就是"新对话"，与右上角按钮文字重复。

**改法**：输入栏整体包进**和底栏同一颗药丸**（`shadow(10dp)` / 50% 圆角 / `navPill` 白底），
三个按钮去掉各自的底色（白底上直接用深棕图标即可），只有**录音中 / 可发送**两个状态
才画实心主色圆——它们是需要突出的状态。两药丸间距从 12dp 拉到 20dp
（同色同阴影叠太近会像"一颗胶囊被劈成两半"）。副标题只在有真实会话标题时显示。

**一个踩过的坑**：第一版顺手给 TextField 加了 `.height(44.dp)` 想让它跟按钮同高，
结果占位文字上下被裁掉——M3 填充输入框固有高度是 56dp，强压 44dp 会截断内部排版。
最终让 TextField 保持自然 56dp、按钮 44dp 居中（药丸总高 56dp）。
（这也说明：**容器该去适应内容，而不是把内容压进容器。**）

验证：`gate.sh` 全过；干净模拟器全量 **84 条** instrumented 全过；
真机复核整页 emoji 0 处、占位文字完整、两药丸分得开。
