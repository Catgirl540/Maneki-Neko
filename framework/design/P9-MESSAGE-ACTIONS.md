# P9 · 消息上的小动作（复制 / 重新生成 / 朗读 / 编辑）

> 状态：已实现。
> 相关：`../app/src/lib/agentSessions.ts`（`rewindTo` / `promptOf` / `lastAssistantId`）、
> `../app/src/lib/useAgentChat.ts`（`rewind`）、`../app/src/components/agent/MessageActions.tsx`（按钮与弹框）、
> `../app/src/pages/SupportPage.tsx`（接线）。

## 是什么

每条消息气泡下面多了一排小按钮：

| 谁的消息 | 能做什么 |
| --- | --- |
| 用户 | 复制、编辑（改完重发） |
| 助手 | 复制、朗读 / 停止、重新生成（**只有最后一条**） |

## 五条设计决定

### 1. 「重新生成」只挂最后一条助手回复

挂到每一条上的话，重新生成中间那条就必须把它**后面**的几轮问答全丢掉。
用户点的是"重说这一句"，代价却是删掉后面十分钟的对话——这种按钮不该存在。

### 2. 倒回重发**退不回服务端的会话记录**，这件事写在界面上

这是整个功能里最容易让人误解的地方，所以单独说清楚：

- 本地这份记录**会**倒回去：那条之后的用户消息、助手回复、工具行、错误通知
  一起从这台设备上删掉。
- 服务端的会话日志**退不了**：助手仍然记得被丢掉的那几句。

于是重发**不是回到当初那个状态**，而是"在同一个上下文里再问一遍"。
后果是真实存在的：重新生成的结果会被原来的回答影响，而不是一次干净的独立采样。

因为这句话容易被误解，编辑弹框里把它写死在按钮上方（`MessageActions.tsx`），
浏览器检查里也有一条断言专门钉它——不许为了界面好看把这句话删掉。

### 3. 换算：按钮在回复上，倒回要倒到**提问**上

「重新生成」的按钮挂在助手回复上（用户点的就是那条回复），但倒回的目标必须是
产生它的那句用户消息。中间隔了一层换算（`promptOf`），漏了的后果是**静默失灵**：
底层按规矩拒绝助手 id，按钮点下去什么都不发生。

这条**实测踩到过**——第一版就是这样，而且伪装得很好：编辑能用（它本来就传用户
消息 id），只有重新生成点了没反应。所以 `promptOf` 有独立的离线断言。

### 4. 朗读和麦克风是两件事

「语音」开关现在**只管麦克风**（要不要出现"按住说话"、要不要留录音状态条）。
听的部分不需要先打开一个模式：任何一条助手回复上都有播放按钮。

两者唯一的耦合是：**按下麦克风会打断正在念的回复**（用户按下来说话，
就是"别念了，听我说"）。反过来关掉麦克风模式**不**停朗读——
关掉一个管说话的开关顺手把声音掐掉，会让"我只是不想说话"变成"我什么都听不到了"。

### 5. 该冻住的时候冻住

下面两种情况下，倒回重发的按钮是禁用的，并且给出原因：

| 情况 | 为什么 |
| --- | --- |
| 这一段**正在回答中** | 倒回会把正在写的那条抹掉，而事件流还在往里写 |
| 有一张**待确认的卡片**没处理 | 那是一笔还没执行的敏感操作，先处理完它 |

## 复制的是原文，不是屏幕上那句话

剪贴板里放的是**这条消息的原始文字**（助手那侧含 Markdown 源码），不是渲染后的文本。
用户复制一段表格是想拿去用，`|---|` 分隔符比丢失的列结构更有用。

浏览器检查里比对时两边要**各自归一化**（去掉 `*` `#` 反引号等符号）再比，
否则一条带粗体的回复会被误判成"复制错了"。

### 刻意没做的事

- **旧版本存档的迁移**：`rewindTo` 只作用在内存里的当前对话，没有写回档格式的版本号。
  这一段不需要迁移——它不改存档结构。
- **重新生成的历史版本**：不保留"上一版回答"，也不做左右切换。主流聊天应用有，
  但这里每一轮都可能牵出资金操作，留一个"上一版回答"等于留一条界面上的歧义。

### 已知没验到的一处

`check-agent.mjs` 里"重新生成之后旧回复被换掉"这条断言，验的是**界面上条数没变多**。
它能挡住"没截断"这一类错误（第一版就是被它挡下的），但**没有**做过一次
"故意让代码追加而不截断"的变异验证——那需要改着源码跑一遍完整检查，
而检查期间页面正被人看着。截断逻辑本身由离线断言
（`rewindTo(two,'u2')` 必须只返回 4 条而不是 6 条）直接钉住，
所以缺口只在"hook 有没有把算好的结果写进状态"这一行接线上。
