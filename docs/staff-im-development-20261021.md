# 工作人员 IM 开发与验证记录

日期：2026-10-21（北京时间）。范围：客服、主管；不接入运维 IM。

## 交付

- 工作人员「IM 机器人」页面：页内二维码、明确绑定、私聊激活状态、重连、解绑、测试提醒、本人静默设置、主管值班规则和通知分页。

- 员工业务工具：客服 17 项、主管 20 项，补齐工作台真实聚合、合法转派、创建审批、留言额外提醒、通知记录和设置查询。
- PostgreSQL 任务事件与通知：事务触发器、接收规则、稳定催办轮次、客户补充合并、备用主管、投递租约及未知发送恢复。
- 员工权限版本、工单原子接手、合法目标校验和请求幂等；代客办理及审批共用原银行提交边界，提交失败回滚后再记录诊断。
- 维护文档、账户模型边界、知识、技能及对应断言同步更新。

配置与使用见 [工作人员 IM](api/staff-im.md)，原方案见 [设计方案](product/staff-im-robot-design.md)。

## 验证环境

使用本机独立 PostgreSQL 16 实例，所有连接只指向四个明确命名、带 `staff_im` 后缀的可丢弃测试数据库；未连接现有银行业务库。因为本机 Docker 不可用，临时 PostgreSQL 运行时安装在忽略的 `.generated/staff-im-test-runtime/`，未增加生产依赖。

微信控制器协议、模型协议和浏览器业务数据均使用隔离夹具。涉及真实 Harness 时连接本机模型协议服务；没有调用付费模型、登录真实微信或向真实私聊发送消息。

## 回归中处理的问题

1. 新增幂等事务最初与旧银行工作单元嵌套；改为显式加入既有银行工作单元，并在最终提交前一起保存业务、审计、幂等结果和通知事件。
2. 最终资金提交阶段失败时，不能返回预先准备的成功回执，也不能向已中止事务写失败记录。现在回滚后检查原审批，记录失败诊断并返回 503，保持原冻结与待处理状态；故障注入后的明确重试通过。
3. 未修改 Git 基线复现了旧手续费断言、贵宾厅请求方法和工单夹具失败。手续费测试改用低 AUM、确实不享受会员减免的新测试客户，保留真实手续费及回滚验证；未改业务收费规则。
4. 旧贵宾厅门禁测试按当前契约使用 POST；客户工单夹具补会员状态表；live 模式代客测试使用合法关联工单，继续验证真实资金侧拒绝。

## 部署与验收边界

本次完成代码及本地验证，**没有部署、开启线上开关、改动线上数据库或进行真实微信投递**。上线前仍需按维护说明升级数据库结构、配置两端一致的服务密钥和员工 Bridge 开关，再由工作人员本人扫码、开通提醒并由主管配置接收池。

`sent` 表示渠道确认，不表示手机送达、微信已读或工单接手。首期为微信文字私聊，人工重发界面、完整排班日历和企微员工入口不在本次实现内。
