# 微信直接设置提醒与网页同步

2026-10-26。用户要求：已绑定微信内完成日程设置，不再跳网页二次确认；浏览器同步正式提醒记录。此前待确认卡同步版本已撤回，本次不重新发布该方案。

## 行为与边界

- “明天上午九点提醒我买花”在微信内直接保存；“提醒我明天买花给女朋友”先追问几点，再按补充时间保存。统一北京时间，不擅自补默认时间。
- 持久化且已核验的本人微信绑定可管理提醒，不依赖短期银行登录。首次未绑定仍须完成银行身份验证，不能由聊天文本指定客户或恢复银行登录。
- 支持查看提醒、按真实编号取消、取消当前私聊最近创建的一条。按实际存储结果回复，重复消息去重；未知保存/投递结果不谎报成功。
- 仅一次性文字提醒。每天/每周等周期请求明确拒绝并要求具体日期；密码、验证码不写入提醒。转账、支付和敏感查询继续原认证/确认链路。
- 网页可见时约 15 秒刷新本人绑定和提醒；恢复焦点、前台或网络立即刷新。保留编辑草稿；请求失败提示错误，客户切换后旧响应不得覆盖新客户。

## 实现

`framework/bridge/im-bank.mjs` 在普通银行登录门禁前加入有限的客户微信提醒回调，验证当前路由归属、绑定版本和取消信号。`im-reminder-chat.mjs` 负责对话补充和调用现有任务事务，`reminder-time.mjs` 负责不依赖模型的北京时间解析。解绑/换绑/停机中止旧路由请求。

`app/src/components/im/ImConnectView.tsx` 和 `app/src/api/im.ts` 刷新正式记录并忽略旧用户响应。不重新挂载已撤回的 `/im/pending` 和待确认卡。

## 同步处理的网站 502

发布前客户银行服务已反复崩溃，账户接口返回 502。原因是既有模拟消费的异步 AI 分类在 scoped 数据库工作单元之外写回，启动恢复中的任务异常也未被完整收束。用户明确授权“先恢复网站和提醒、暂时停用分类”。

临时修复仅暂停 `server/index.mjs` 传入的异步分类回调，并让没有分类器的新模拟消费明确标记 `classificationState=failed`，保持“其他”分类并显示“分类器暂不可用”。启动时原任务恢复在已有事务内将未分类任务标为失败；不删除交易、不改金额、余额、账户号或冻结额。独立严格内存夹具验证启动、重启、未分类状态、单资金账户和一分模拟消费扣款守恒，无真实模型或银行请求。

恢复检查发现客户 Agent 会随客户银行停止，需要一起启动；最终恢复只重启客户银行与客户 Agent。银行当前接口已恢复。修复前文件保存在私有备份目录 `/var/backups/maneki-classification-off-20261026T122726Z`；提醒发布备份目录以发布记录为准。自动分类事务链路仍待独立修复，不能据网站恢复宣称分类功能完成。

完整源码导出曾因拟设 0644 权限被自动审批拦截，未执行。取消该导出，仅使用此前已获准的相关源码读取结果完成兼容处理，没有创建该可公开读取的源码快照。
