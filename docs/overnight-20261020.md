## 本地使用示例与验证界限

- 构建 Agent：`npm --prefix framework run bootstrap:customer`。生产与自检 profile 必须同时包含精确注册的 34 项银行工具，不通过放宽全局白名单来消除报错。
- 本地完整测试：`node tools/local-test-env.mjs integration`；全部后端：`node tools/local-test-env.mjs server`；真实 Harness 本地模型协议：`node tools/local-test-env.mjs agent`。同组库一次只运行一个上述命令。
- 对话示例：“先查可选理财产品，再比较其中两款的期限、风险和费率，拟投入一万元。”代码必须来自银行产品目录；意图或产品不明确时补问，金额是估算输入，不是购买指令。当前没有另做产品对比网页按钮，通过 Agent 工具提供能力。
- 对话示例：“查看未来 7 天的续费清单，哪些是停用的，有没有同名签约？”调用 `bank_analyze_autodebits({days:7})`，不是创建定时提醒；要停用时再明确准确合约编号并使用原确认流程。IM 有效绑定可直接查询，网页查询仍有确认卡。
- 流水示例：“核查我的人民币账户流水，有没有重复扣款或金额突增？先看 100 条样本。”先查本人账户/币种 ID，再用 `bank_review_transactions`。必须说明覆盖及排除范围，按返回编号核对回单；不要把候选认定为实际重复收费、已签订订阅或欺诈。
- 定投示例：“先查定投目录，把其中适配我的产品按每周 100 元保存计划，再暂停/恢复/取消这个计划。”代码与编号必须来自 `bank_list_investments`；创建及恢复需要确认页支付密码。当前仅管理计划，不自动扣款或预约执行。网页入口 `/wealth/investments`，暂停/恢复/取消按钮需核对弹窗。
- 统计示例：“查看 2026 年 9 月支出、和前一个月比如何，再看最近 30 天美元现金流。”用 `bank_get_spending({month:'2026-09'})` 与 `bank_get_cashflow({days:30})`，从 `byCurrency.USD` 展示美元；两者窗口不同。说明北京时间、查询时点、上月是否有基数，本月至今不是等天数比较。网页 `/analysis/statistics` 可直接切月份和币种。
- 在途示例：“查看我的美元在途转账，核对这笔本金和费用冻结后撤回。”先查询本人余额分区、流水和实际交易详情，以准确 `transactionId` 调用 `bank_recall_transfer`；确认卡显示对应币种及本笔冻结合计。清算/已结算/过期或不明确的交易不能撤回，其他冻结不变；这不是退款或定时任务取消。专项可用 `server --test-name-pattern=foreign.currency.transfer.holds`，真实 Agent 撤回已纳入整合门禁。
- 浏览器完整回归：设置本机 `CHROME_PATH` 后执行 `node tools/local-test-env.mjs agent --browser`；仍走真实页面登录、验证码和支付密码。非浏览器已通过而仅修复浏览器时用 `agent --browser-only`。聚焦后端新场景可使用 `server --test-name-pattern=investment plans`；这些限定范围的运行不能算全量通过。
- 轻量维护门禁：`node tools/check-contract.mjs`、`node tools/check-routes.mjs`、`node --test tools/api-methods.test.mjs`；内存单账户在途回归 `node --import ./tools/ts-resolve-hook.mjs tools/check-transfer-holds.mjs`，备用引导 `node --import ./tools/ts-resolve-hook.mjs tools/check-support-guidance.mjs`。这些不调用服务器或模型。知识检索 `npm --prefix framework run test:knowledge`，当前 90 道固定问题。
- 验证使用隔离 sandbox 银行及本地模型协议夹具，未运行真实 OpenRouter 意图识别评分、未调用真实银行上游，也未触碰公网客户数据。比赛原始评分、模型限制和交付形式仍需用户提供正式资料后核定。
