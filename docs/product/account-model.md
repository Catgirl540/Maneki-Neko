# 资金账户、币种余额与银行卡

确认日期：2026-10-16。本文是账户模型的维护依据；旧设计稿、演示快照和历史文档不能覆盖以下约束。

## 产品约束

- 每位客户只有一个储蓄资金账户、一个对客银行账户号。
- 同一账户可持有多币种余额。人民币、美元、港币分别记账，不直接加总。
- 同一账户可关联多张银行卡；卡号与银行账户号不同，卡片不单独存钱。
- 每位客户至多持有一张 Visa 卡和一张银联卡。使用中、锁定、寄送中、挂失（lost）的卡占用对应卡组织名额，换发卡（replaced）为历史卡不占名额；申请已占名额的卡组织直接被拒且不收费，换卡不额外占名额。普通锁卡/解锁只接受 active/locked；寄送中不能借此激活。正式挂失、解挂均验证支付密码；解挂恢复原 active/locked/pending 状态且支付保持关闭，不冻结资金账户。
- 申请新卡、换卡、锁卡及切换当前卡片都不创建或切换资金账户。
- 支付密码连续输错 5 次冻结客户账号的支付与敏感操作，保留登录、普通只读及客服能力；错误次数按客户持久化，重新登录、重启及支付密码重置不能解冻，须工作人员关联在办工单并核验身份后解除。账号冻结与卡片锁定、单笔资金预留分别管理，不改余额、预留、流水或账户归属，不创建资金账户；见 [密码与账号安全](../api/security.md)。
- 会员等级（普通/金卡/白金/钻石）按上月日均 AUM 评定：资金账户折人民币余额（含外币按中间价折算）+ 理财持仓市值 + 现金管理余额，不含信用卡/授信额度。门槛 ¥0 / ¥10 万 / ¥50 万 / ¥300 万；升级即时、降级连续 2 个评定周期缓冲。等级只用于评级与权益（制卡费减免、换汇点差、转账费减免、VIP 工单、贵宾厅、专属经理/顾问、理财优先购），升级与降级不创建账户、不修改账户号、不改变余额或已有流水。规则见 [会员制规则设计](./membership-rules.md)。
- 换汇在该账户的币种余额之间记账，首次兑换仅初始化目标币种余额。
- 转账按币种分区记账：付款方从本人账户下任一币种余额出账，报价、限额、手续费与回执都按该分区币种；本行收款方按到账币种（`payeeCurrency`，省略即付款币种）入账，同一资金账户下没有该币种余额时自动开立 0 余额分区再入账，不新建账户、不改账户号与卡片归属。重复收款沿用同一分区；跨币种时按确认报价折算到账金额。
- 在途转账在实际付款币种分区预留本金及费用；撤销、拦截或到账前的解冻使用同一分区，兼容旧分区映射，不得只查人民币主记录。只释放本指令记录的冻结额，其他指令和币种不变；到账再按原确认条件扣款，不将解冻说成退款或另建账户。详见 [在途转账](../api/accounts.md#在途转账与撤销)。
- 定时转账是客户明确确认时间、完整收款账号及金额并验支付密码后保存的一次性境内同币种指令，不保存密码、不提前冻结或扣款。仅演示沙箱后台到期执行原转账规则，包含余额和大额在途风控；到期前可按版本取消，执行和状态持久化属于同一事务。执行异常必须回滚相关客户全部变化，不能吞掉错误后提交部分资金变更。live 模式不运行演示执行器。
- AA 收款按总整数分分摊，余分依参与者顺序分配；仅保存收款请求，回款必须匹配本人该币种真实成功转入流水，流水不可重复认领。不扣参与者资金、不虚增本人余额；催收只生成文字，不发送给他人。
- 不提供自己名下银行卡之间的资金划转。向其他客户转账仍须核验收款人并确认。
- 理财账户是投资资格和委托关系，不是第二个储蓄资金账户；申赎通过唯一资金账户结算。
- Agent 产品对比只读取产品目录与本人的测评状态，可估算拟投入金额的费用与门槛，不创建资金账户、不冻结或扣除资金，也不构成申购授权。
- 理财匹配按本人有效风险测评、金额和期限作透明规则筛选，排序与排除理由可见，不预测收益。每次申购保留独立持有批次及封闭期；赎回按已开放批次先进先出，只对未满七天的适用批次收取短期费。演示赎回即时增加唯一资金账户余额，回执明确 sandbox-immediate，不写预计 T+1。
- 定投计划绑定本人唯一资金账户的人民币余额；保存、暂停、恢复或取消只管理计划记录，不新增账户、不改余额或投资历史。当前未开放定时扣款执行器；创建/恢复仍验证支付密码和适当性，状态更新以版本防止并发覆盖。
- Agent 续费清单只读取本人银行已有自动扣款合约，按北京时间窗口统计下一次扣款并分币种展示；不新建资金账户、不修改余额、不展开周期或创建后台提醒。停用仍使用独立的合约确认操作，见 [自动扣款接口](../api/autodebits.md)。
- 卡片激活（`POST /api/cards/:id/activate`）只把待激活卡改为使用中，需支付密码；不创建账户、不改余额与限额。模拟消费（`POST /api/cards/:id/spend`）在预设商户上模拟刷卡：扣的是该卡 `accountId` 对应币种分区的可用余额，不新建账户、不动其他币种、不改卡与账户的归属关系。交易分类由服务端分类器**后台**判定（与真实刷卡同一路径；模型链每模型重试 3 次，全失败落 other 并标记 failed）：流水先以 other 落账、`classificationState=pending`，分类完成后回写，不阻塞记账与响应；写账时商户类别限额按「其他」桶校验，分类完成后不回溯。锁定、待激活、已换发或关闭线上支付的卡不得消费，并受单笔上限、单日限额、线上渠道限额与商户类别限额约束。演示功能只在非 live 模式开放。
- 月度支出和现金流由同一资金账户的实际记账分区分别统计 CNY/USD/HKD，账户内换汇不当作收支，不新增资金账户。统一北京时间自然日/月和查询截止时点；月环比对所选月的上一个完整月，无基数显式标记。网页与 Agent 均不得混币或把查询失败当零金额。详见 [统计接口](../api/accounts.md#收支统计)。
- Agent 流水核查只分析本人账户币种下的有界第一页样本，按真实记录给出待核对候选与证据；不跨客户或直接合计外币，不修改账户、余额或流水，不把样本当作完整月/年度报告，也不据候选自动锁卡或退款。
- 月/年账单报告聚合本人所选币种全部成功记账流水，按北京时间自然月/年和查询截止时点统计；年度包含十二个月及分类汇总，支持 CSV。内部换汇与未成功记录排除，当前周期标为截至查询时点；此口径独立于有界异常/周期订阅候选样本。
- 生日联动由本人提供联系人、关系和日期，经预览、独立确认及支付密码授权后保存。到预留日只减少指定币种 available，账面 balance 不扣；取消或到期仅释放该计划原预留，其他冻结保持不变。提前两天生成鲜花蛋糕待办；独立确认后为等待商户接入，无真实订单、不消费。每计划归属客户，银行余额与任务状态同事务持久化，详见 [生日联动](../api/linked-birthdays.md)。
- 微信日程提醒只保存客户明确确认的文本、时间和本人接收私聊，复用现有 IM 控制器到期投递，不查询余额、不创建资金账户、不执行转账或定投。工作台任务库按客户隔离；提醒授权独立于内存银行登录，重启后仍保留，解绑/更换绑定使旧提醒失效。银行资金账仍在 PostgreSQL，不写入工作台任务库。
- 网页客户可在 IM 连接页生成本人的微信登录二维码；扫码任务仅归当前银行登录客户，扫码后须另行确认绑定。渠道接收身份来自微信确认结果，禁止客户端指定或改绑其他客户；扫码不创建资金账户、不恢复其他客户会话，也不授权资金操作。
- 工作人员微信仅关联客服/主管的已有员工身份；任务通知库只保存任务路由和投递状态，不创建或拆分客户资金账户。代客操作、审批及幂等记录共用原银行业务提交边界，转账处置仍处理原在途指令。微信提醒不等于金融授权或实际执行成功，见 [工作人员 IM](../api/staff-im.md)。

## 接口与界面

`GET /api/accounts` 对已开户客户返回一个 `Account`。`currencyBalances` 是其币种记账分区，每项共享同一个对客 `accountNo`。分区 `id` 用于既有换汇、流水、导出及 FPS 接口，不是新银行账户。

账户页显示资金账户和各币种余额；换汇选择卖出、买入币种；转账选择付款币种分区与到账币种，网页银行账户转账默认人民币到账，付款币种变更不自动更改到账币种；账单按币种查看；卡片页选择卡片时资金账户保持不变。不得用卡产品名代替账户或币种名称。

理财中心 `/wealth` 的持仓市值、本金与盈亏只采用理财概览口径，不加总储蓄余额、存钱目标或计划金额。申赎继续通过唯一储蓄资金账户结算；`/wealth/records` 仅复用该账户的申赎相关分页流水，不据记账状态推断份额确认或赎回到账。结构与兼容路由见 [理财中心说明](./wealth-workspace.md)。当前虚构产品、费率及份额/到账等演示简化以 [理财产品目录](./wealth-products.md) 记录；不能把产品条目、理财资格或旧活钱数据域视为新的储蓄账户。

服务降级时的固定客服引导不实时查询资金账户、变更银行卡或执行业务，不生成余额、当前利率或到账结论。内存回归须使用不同客户各自的唯一资金账户验证双方守恒，不能为了旧脚本的 `accounts[1]` 假设恢复自有多账户划转。

## 兼容与迁移

当前 PostgreSQL 后端与浏览器模拟均使用档案 v24：`accounts` 保存唯一资金账户，内部 `currencyBalances` 保存外币记账分区；`retiredBalances` 保留被合并的旧账本行并将其余额归零。v24 增量初始化定时转账、AA 与生日计划数组，不重置既有余额、冻结、流水或持仓。PostgreSQL 的兼容表 `bank_accounts` 保存这三类内部记录，表行数不等于客户资金账户数。生产入口不再使用 SQLite。

核心 PostgreSQL 迁移版本 2026102701 增加 lost 约束及 bank_background_tasks 到期索引；索引仅有客户 ID、任务 ID、类型与到期时间，计划内容保持在客户加密扩展域中。迁移回填旧加密计划的索引，执行器按索引分页加载相关客户；不为发现任务解密全体客户档案。

旧同币种账户合并余额、可用余额和账务关联，旧 ID 经 `accountAliases` 解析，旧账号经 `accountNumberAliases` 解析；不同币种分别保留。SQL 历史交易的原 `account_id`、交易编号与时间不变，读取时投影到当前分区，并保留 `legacyAccountId`。历史回单原始账号快照不重写。迁移必须可重复执行，不能重置数据库、清空流水或借合并解除冻结。余额迁移产生新的平衡凭证，不删除或重写原凭证；任何持久化失败都回滚整笔业务。

这些说明针对当前仓库实现。公网后端若使用其他存储版本，须核对其适配与迁移，不能直接覆盖生产数据库。

## 修改门禁

后端按需客户投影和增量流水写回不改变唯一资金账户、币种分区、原流水身份或金融事务边界；部分缓存不能覆盖其他客户索引。内存治理与容量验证见 [后端内存维护说明](../backend-memory-20261022.md)，回归须包含跨客户守恒、回滚及重启，不能通过截断历史或删除流水降低内存。

微信、企业微信绑定仅关联渠道私聊身份与已有客户，不创建、切换或拆分资金账户。IM 会话沿用银行登录归属和业务确认；渠道标识、机器人标识和会话编号都不是银行账户号。接入与验证见 [IM 接入说明](../api/im-agent.md)。
有效 IM 绑定可复用现有登录进行本人资金账户的白名单只读查询；服务端逐次检查归属和参数，不要求用户逐次打开查询确认页。此行为不新增账户、不扩展到他人数据，也不免除写操作或敏感卡信息的确认和验证。

修改账户、卡、换汇、流水、开户、客户隔离或相关文档时，同一提交更新本文、接口说明、知识/技能和对应断言。

在仓库根执行：

```bash
npm --prefix app run check:account-model
npm --prefix server run check:integration
```

网页 `npm run build` 的 `prebuild` 会自动检查维护文档；第一项额外检查内存业务夹具。整合门禁需要四个专用可丢弃的 PostgreSQL 测试库，缺少连接直接失败；配置与框架构建步骤见 [后端维护说明](../../server/README.md)。它验证迁移、重启、旧 ID 写入、跨币种 FPS、手续费原子写入、并发、幂等、live 模式、Agent 持久化与角色隔离。旧 SQLite 集成入口仍明确停用，`server/smoke.mjs` 只对已有服务做只读探活。另按改动运行网页构建及知识/技能校验。只有用户明确改变产品要求时，才可修改上述模型及门禁。

即时转账须在银行提交事务中验证支付密码，密码不得写入在途指令、员工审批或流水。定时与在途指令使用已授权的内部执行路径，不保存密码；客户端仅在服务端声明支持该保护时提交。该规则不改变唯一资金账户及币种分区模型。
