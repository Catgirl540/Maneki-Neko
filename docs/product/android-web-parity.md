# 安卓与网页功能对齐

本地实现日期：2026-11-01。基准为 `app/src/App.tsx` 当前网页路由和 `android-app/` Kotlin 工程。只修改与本地验收；本轮未提交、部署或发布。账户约束以 [账户模型](account-model.md) 为准。

## 资金操作基础

- 转账、在途撤销、换汇、理财申赎、开卡/换卡、定时创建/取消、AA 发起/取消/付款/回款核对/催收、定投管理、生日创建/取消/待办确认和模拟消费均先检查服务端原子恢复能力。
- 应用私有偏好仅保存归属客户的随机操作编号及类别；不保存支付密码、授权请求体或金额。服务端归属标识按摘要分槽，不因切换手机号串号。
- 完整业务回执通过校验才清除记录；断流、不完整成功响应、进程重建或业务错误遗留的未知请求先核查。已处理读取原结果，未处理原子封存旧编号，阻止迟到提交。断网保留记录并阻止新资金操作。
- 最终支付密码仅放入授权请求，结束即清空界面；不将密码交给恢复机制。服务端仍负责验密、冻结、报价与账户归属校验。
- 不能把此协议解释为外部银行已接入，也不能用新版安卓直接绕过旧后端缺失的能力。

## 网页路由对应安卓入口

- `/dashboard`：总览、真实账户余额与近期交易、快捷入口、助手入口。
- `/accounts`、`/receiving`：存款、转入收款信息；同一资金账户按币种展示。账户号取自服务端，无虚构卡号或账户余额。
- `/cards`：银行卡列表、申请与换卡、地址和费用确认、激活、锁卡/解锁、挂失/解挂、限额和支付设置、验密查看敏感卡信息。寄送页显示实际地址记录；后端没有物流状态时明确说明。
- `/spend`：更多服务 → 模拟消费。选择真实使用中的卡、共享目录中的预设/自定义/Stripe 商户、金额及摘要；可订阅商户须明确勾选。回执显示服务端交易、币种、可用余额与分类状态。真实商户收单仍未接入。
- `/transfer`：转出 → 银行账号、香港手机号、跨境支付通/FPS；付款和到账金额双向换算，独立币种，服务端报价到期后重新获取。FPS 的手机号、电邮、FPS ID 先解析登记并在最终确认前复核；账户方式核对姓名及银行。收款人簿支持真实检索、选择及备注保存。
- `/transfer` 的定时与 AA：转出或更多服务 → 定时转账与 AA。支持境内同币种定时指令的创建、版本取消及状态；均分/分项 AA 按整数分逐项分摊，本人份额与成员金额独立；手机号站内通知、成员验密付款、收款状态、版本取消及催收文字。旧的非站内清单可核对已有成功回款，不能据通知虚增到账。
- `/transactions/:id`：交易详情。币种、原币金额、汇率、费用、备注及账户来自真实流水；在途窗口内独立确认撤销。可保存交易明细 PDF，标明非银行签章电子回单。
- `/analysis`：交易记录支持服务端筛选、分币种分页加载和相同条件 CSV 导出；账单报告支持历史月度、年度、CNY/USD/HKD 及 CSV。年度每月数据和分类遵循完整账本口径，不拿近期样本代替。
- `/analysis/statistics`：消费分析，可选历史月份、币种和 7/30 天现金流。失败显示错误，不把旧月份或其他币种的数据当当前选择。
- `/analysis/budgets`：支出预算的创建、编辑、启停、删除、当日使用情况、积分及额度券；平台目录与网页共用生成源。
- `/analysis/autodebits`：自动扣款真实合约列表及启停；当前未开放执行器，通知只描述规则日期。
- `/cashflow`、`/credit`：工资与备用金、借款与分期。复用已有工资规则保存、备用金状态、借款申请和已存在分期展示；网页同样未开放的备用金支用/还款不做虚假入口。
- `/wealth`、`/wealth/products`、`/wealth/holdings`、`/wealth/records`：理财四段、适当性前置、产品/持仓、实际申购及赎回。更多服务的各入口准确进入对应段；记录按申购/赎回关键词分页，不再只筛最近 50 条。
- `/wealth/plans`：储蓄与计划 → 存钱目标、凑整配置；定投创建/暂停/验密恢复/取消，版本冲突不覆盖；生日联系人与日期、服务端预览、独立验密确认、原币种预留、取消和商户待办确认。不因目标或计划另建资金账户。
- `/wealth/cash-management`：储蓄与计划 → 现金管理；真实余额与收益、保留金额和规则开关。设置只保存规则，未开放自动转入。
- `/wealth/insurance`：保险保障列表、已有保单及实际验密投保接口；使用原人民币资金账户结算。
- `/security`：安全中心的真实总览、风险规则、登录密码、支付密码和身份核验；个人资料新增修改手机号流程。冻结与解冻权限保持服务端约束。
- `/security/membership`、`/security/invitations`：会员等级及真实资产/权益/贵宾厅核销、邀请与奖励。移除固定会员进度和固定寄送资料。
- `/assistant`、`/support`：助手及历史、既有确认授权流程；智能服务入口按 `GET /agent-api/services` 渲染（与网页同一份清单，当前 8 项），取不到时隐藏且不回退本地副本；另有人工客服工单入口，可提交问题、查看本人工单与留言。助手健康检查同时读取服务状态，HTTP 200 不代表模型已可用。
- IM 连接及 `/reminders`：生成本人微信二维码、状态查询、验证码、独立确认绑定及解绑；微信日程支持本人绑定选择、内容和北京时间核对、创建/记录/取消。权限、到期投递与身份隔离由现有 IM 后端负责。
- 登录/开户：保留现有登录页布局调整及真实服务端开户流程。忘记密码有明确客服指引；通知设置和语言页面说明当前后端/界面能力，没有可点击但无效果的开关。

## 验收与复现

- 构建：JDK 21 / Gradle 8.14，`:app:assembleDebug :app:assembleDebugAndroidTest --offline`。
- `FinancialRecoveryTest`：本地恢复持久化与客户隔离、并发启动、清除归属、完整与断流响应、报价一致性、AA 余分与分项、严格北京时间日期和 FPS 标识。
- `node tools/check-android-catalog.mjs`：商户、预算和订阅目录与共享源完全一致。
- `node tools/check-android-parity.mjs emulator-5554`：由本地测试夹具创建可丢弃 PostgreSQL 数据及两位演示客户，真实 Android → HTTP → PostgreSQL 调用，验证跨币种与 FPS 转账、定时创建/取消、AA 通知/付款/取消、目标与凑整、定投创建/状态、现金管理、生日预览/创建/取消、模拟订阅、客服工单、分页和 CSV；最终核对账务守恒。测试令牌只临时写应用私有目录并清理，截图存 `/tmp/maneki-parity-*.png`。
- `npm --prefix app run check:account-model`：唯一资金账户文档和行为断言。
- `node tools/local-test-env.mjs integration`：专用 PostgreSQL 门禁，覆盖迁移/重启/并发/跨客户、版本、支付密码、在途、原子恢复封存及迟到提交；同时验证桥接与 Agent HTTP。
- IM 的二维码、绑定、提醒和隔离由现有桥接测试覆盖；真实手机扫码、微信渠道实际投递、短信和外部清算需要配置对应服务，本地夹具通过不代表这些外部能力已经实测。

## 仍由后端或外部服务限制的能力

通知偏好保存、英文界面、物流追踪及正式签章回单没有对应服务；页面明确说明限制。短信/人脸仅支持当前沙箱凭证，不调用设备摄像头做真实活体。定投、现金管理、凑整及自动扣款仍只管理规则，不能显示为自动执行成功。微信和助手依赖运行中的绑定/控制器及模型配置；缺失时显示实际错误。所有资金验收仅使用隔离测试数据。

若后续发布，必须先部署支持恢复协议的银行服务端，再发布新版安卓；本清单不构成提交或发布授权。
