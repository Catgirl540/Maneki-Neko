# 虚构理财产品目录与演示规则

更新：2026-10-20。面向开发、设计与验收；网页结构见 [理财中心](wealth-workspace.md)，接口见 [理财申赎](../api/wealth.md)。

## 1. 范围与事实来源

本项目为比赛演示。以下产品、发行方“招财猫理财有限责任公司”、净值、费率、基准和持仓配比均为项目内虚构配置，不代表真实发行、代销、合作机构或真实市场业绩。资产明细中的现实机构、指数和证券名称只是模拟配置素材，不证明实际投资或授权。

- 服务端目录：`server/domain/state.mjs` 的 `WEALTH_PRODUCTS` 与 `seed()`；业务：`server/domain/index.mjs`。
- 浏览器模拟目录：`app/src/api/mock/db.ts`；模拟业务：`app/src/api/mock/index.ts`。
- 普通理财、定投、旧活钱是三套不同目录，代码不能互换。网页将入口整理到同一中心，不表示底层产品已合并。
- 金额字段为整数分，以下表格换算成元；费率字段为小数，表格换算为百分比。客户当前可用产品与数值仍需查询接口，不能拿本文件充当实时行情。
- `live` 模式未接入合作银行时，当前理财相关能力返回 `BANK_NOT_CONNECTED`，不能回退到这些演示产品。

## 5. 交易规则与已知简化

- 每位客户只有一个储蓄资金账户。理财开通建立投资资格及委托关系，申购扣款、赎回回款使用该资金账户；不按产品另开户。
- 申购需已开通理财、有效测评、风险匹配、满足起购及递增规则、余额足够，以及本人抄录风险语句和支付密码。C1–C5 分别最高匹配 R1–R5；会员等级不豁免这些条件。
- 递增条件当前为“总申购金额能被 `stepAmount` 整除”，不是“起购金额之外的部分递增”。
- 同一产品合并显示持仓，买入净值按份额加权；每次申购保留独立批次及封闭期，先进先出赎回已开放批次，不能提前赎回追加的未开放份额。持仓返回当前 redeemableShares；没有可赎份额时 closed=true。
- 封闭期结束只允许发起赎回，不自动赎回。份额不得超过持有份额；省略份额代表全部赎回。当前赎回不另验支付密码，仍需用户明确确认。
- 申购演示会即时扣款、增加持仓并返回确认份额；赎回演示会即时增加资金账户余额并减少持仓，回执明确“演示资金已即时到账”，提供 fees、settlementMode=sandbox-immediate 和 settledAt。目前没有真正的在途申赎、交易日清算或独立理财订单状态机。
- 当前份额换算直接以“分金额 ÷ 单位净值”计算，属于内部演示份额口径，与通常按元计算的份额不一致；不能作为接入真实基金份额的计算规范。市值仍按“内部份额 × 净值”得到分金额；昨日收益用当前份额与序列末两点差推导，不是逐日持仓收益账。
- `LCB-FIXED-365` 在优先购窗口内要求钻石；`LCB-MIXED-180` 要求白金及以上。当前窗口在目录模块加载时设为其后 10 天，重启会重新生成，不是固定销售日历。以接口返回的 `priorityOpenAt` 与服务端判断为准。
- 网页交易记录按现行“申购 · ”/“赎回 · ”标题和 `other` 分类查询资金流水，不是完整委托订单源；后续若改变流水分类或标题，必须同步调整查询，不能假设所有历史记录都仍能命中。

## 8. 维护与校验

修改产品名称、代码、风险、起购/递增、期限、费率、净值或基准时，同一提交核对服务端与浏览器模拟目录，并同步产品详情、知识/技能及相关断言。不得用旧截图或归档目录恢复旧参数。

本文件六个标记块由代码目录生成；普通运行只校验，不改文档：

```bash
node --import ./tools/ts-resolve-hook.mjs ./tools/check-wealth-products.mjs
node --import ./tools/ts-resolve-hook.mjs ./tools/check-wealth-products.mjs --write
npm --prefix app run check:account-model
npm --prefix framework run knowledge
npm --prefix framework run skills
```

`--write` 仅刷新本文件目录表，不修改业务、余额或客户档案。脚本同时比对服务端与浏览器模拟的产品配置；发现差异先修正产品定义，再更新文档。知识库只收录“虚构演示”和能力边界，不复制这里的固定收益数字作为在线回答依据。
