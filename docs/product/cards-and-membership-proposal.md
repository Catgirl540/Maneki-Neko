# 银行卡与会员体系

日期：2026-10-19（2026-10 实现版；会员部分已过时）。卡数量限制仍为现行规则。

> **历史说明**：会员部分（白银/黄金/铂金/钻石、储蓄日均评定、旧订阅 legacy）已被 2026-10-20 用户定稿的纯资产分层新方案取代。现行会员规则、四档门槛、AUM 口径与权益见 [会员制规则设计](./membership-rules.md)。本文第 2、3、4 节中与会员相关的段落仅作历史记录，不再作为实现依据。

卡数量限制（每位客户至多一张 Visa、一张银联）继续有效。本文保留卡数量限制、换卡原子操作与服务端名额强制的维护口径。

## 1. 已确定的数量与建议落地口径

每位客户继续只有一个储蓄资金账户，Visa、银联卡各至多一张，两种卡共享该账户的多币种余额。两种卡均为借记卡，不因卡组织或会员等级产生授信。

- 可以不持卡、只持一种卡，或各持一张；开户不强制同时办两张卡。
- 制卡中、寄送中、待激活、使用中、锁定的卡均占用对应卡组织的名额，锁卡不能释放名额。
- 同组织已有卡时引导管理或换卡，禁止再次申请并收费。
- 换卡在同一笔原子操作中使旧卡失效、新卡接替名额；失败不扣费、不作废旧卡。历史卡保留，不能作为可支付卡使用。
- 实体卡和独立虚拟卡共用同组织名额。已有卡的支付令牌、受控一次性卡号属于该卡的凭证，不形成独立资金账户或额外持卡名额。
- 新卡、换卡和会员升级均不创建资金账户，不修改账户号，不改变余额或已有流水。

## 2. 分级方式（历史，已被新方案取代）

统一客户会员等级，Visa、银联共享等级与权益。卡组织负责支付网络，会员等级负责客户权益；不为每个等级再建立一种银行卡产品。

> 现行规则见 [会员制规则设计](./membership-rules.md)：普通 / 金卡 / 白金 / 钻石四档，按**月均 AUM（储蓄 + 理财持仓 + 现金管理）**评定，门槛 ¥0 / ¥10 万 / ¥50 万 / ¥300 万；升级即时、降级连续 2 期缓冲；付费订阅已彻底删除（含 `legacy` 字段）。

以下为历史口径，不再实现：四档白银、黄金、铂金、钻石；白银开户即享，黄金日均 1 万元、铂金 10 万元、钻石 50 万元；评级资产只含储蓄余额；旧订阅记录收进 `legacy` 只读保留。

评定：按北京时间每日末快照统计，上月日均资产决定本月等级。现行实现同样保留日终快照、缺日按 0 计与惰性评定，但快照存的是当日 AUM（不只储蓄），评定入口为会员中心、申卡、换汇等。

## 3. 权益边界（历史）

所有会员均保留转账、银行卡安全管理、电子账单、助手和转人工等基础功能。

> 现行权益以 [会员制规则设计](./membership-rules.md) §4/§5 为准：境外转账手续费减免、客服 VIP 通道、专属客户经理、理财优先购、机场/高铁贵宾厅、专属理财顾问、境外汇款手续费减免；旧的两项已接通权益（制卡/换卡费减免、换汇点差折扣）并存保留。生日礼遇暂缓，仅展示为「规划中」。

历史口径：制卡/换卡费年度减免（白银无、黄金半价 1 次、铂金全免 1 次、钻石全免 2 次且含寄送费）与换汇点差折扣（黄金 9 折 / 白金 8 折 / 钻石 7 折）。这两项在新方案中继续生效，档位门槛按新方案。减免次数按自然年重置，申卡/换卡前由后端计算实付报价（`feeQuote`），成功办理后核销并写入权益使用记录；前端显示等级不等于已经获得减免。升级不改变风控、风险测评、支付确认或实际转账限额。

## 4. 页面组织（已实现）

申卡弹层列出全部卡产品：已占名额的产品置灰并标注「已持有同组织卡」与换卡提示；实付金额按 `feeQuote` 展示（减免时划去标价）。历史卡保留在卡片列表中，不占名额、不可操作。

“会员与订阅”已改为“会员中心”（现行），展示等级卡与 AUM 升级进度、生效权益、贵宾厅额度与核销、各等级对比和评级记录。旧套餐订阅已彻底删除（类型、接口与 `legacy` 字段均不再存在）；`user.memberTier` 由 AUM 派生，不再保存等级文案。

会员升级立即更新数字展示；已寄出的实体卡保持原样。需要新卡面时由用户主动申请同组织换卡，不自动换号、收费或寄卡。

## 5. 实现与迁移

新演示档案已调整为每组织最多一张在用卡（1 张在用 Visa + 2 张 replaced 历史卡：1 银联、1 Visa）。服务器存量重复卡不静默删除或作废：全部保留为 `replaced`/历史记录并阻止继续增发；余额、冻结、流水和历史卡记录全部保留。旧会员订阅字段在新方案中直接删除，`normalizeMembership` 对全版本档案幂等修补（silver → standard、删除 `current`/`plans`/`legacy`、补 `belowPeriods` 与贵宾厅计数）。

名额强制在服务端 `openCard`（HTTP / mock / Agent 共用同一 domain），校验先于支付密码与收费；HTTP 层请求串行化 + 单元事务保证并发安全，`openCard`/`replaceCard` 走既有幂等键。换卡为单笔原子操作。

## 6. 实施与验收

数量限制由后端按客户和卡组织校验，并覆盖并发、幂等、网页、App 与 Agent 入口；前端禁用重复申请仅用于提示。换卡按同组织处理，重复提交不重复扣费、发卡或消耗权益。

落地时同一提交更新账户模型、银行卡及会员接口说明、知识库、技能和断言；回归现有资金、锁卡、换卡、确认与取消流程。会员需要独立的日终快照、评定记录和权益使用记录，不能只修改前端标签。
