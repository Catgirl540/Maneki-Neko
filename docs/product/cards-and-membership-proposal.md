# 银行卡与会员体系草案

日期：2026-10-19。本文用于明确下一轮产品规则，不代表已实现或已发布。

接手入口：[Agent 接手说明](../../design/handoff/AGENT-HANDOFF.md)。用户已要求暂由其他 Agent 接手；本草案尚未进入业务实现。用户明确确认的是 Visa、银联各至多一张；会员分级方式、门槛和权益仍待选择，下面其余细节为建议口径。

## 1. 已确定的数量与建议落地口径

每位客户继续只有一个储蓄资金账户，Visa、银联卡各至多一张，两种卡共享该账户的多币种余额。两种卡均为借记卡，不因卡组织或会员等级产生授信。

- 可以不持卡、只持一种卡，或各持一张；开户不强制同时办两张卡。
- 制卡中、寄送中、待激活、使用中、锁定的卡均占用对应卡组织的名额，锁卡不能释放名额。
- 同组织已有卡时引导管理或换卡，禁止再次申请并收费。
- 换卡在同一笔原子操作中使旧卡失效、新卡接替名额；失败不扣费、不作废旧卡。历史卡保留，不能作为可支付卡使用。
- 实体卡和独立虚拟卡共用同组织名额。已有卡的支付令牌、受控一次性卡号属于该卡的凭证，不形成独立资金账户或额外持卡名额。
- 新卡、换卡和会员升级均不创建资金账户，不修改账户号，不改变余额或已有流水。

## 2. 推荐的分级方式（待确认）

推荐采用统一客户会员等级，Visa、银联共享等级与权益。卡组织负责支付网络，会员等级负责客户权益；不为每个等级再建立一种银行卡产品。

建议四档：白银、黄金、铂金、钻石。会员由资产达标获得，移除当前按月购买金卡、白金套餐的设计；不自动取消或改写旧订阅记录。

第一版可讨论的演示门槛为：白银开户即享，黄金上月日均资产满 1 万元，铂金满 10 万元，钻石满 50 万元。以上是本项目的建议参数，尚未确认，也不是 ZA 或微众的现行门槛。

评定建议：按北京时间每日末快照统计，上月日均资产决定本月等级；当月新客从白银开始。展示统计区间、下次评定日期和升级差额，不把当前余额直接当作月日均资产。缺少历史快照时不编造历史达标情况。

评级资产先采用可核验的储蓄余额与已确认理财持仓，合并资金账户各币种前必须使用有日期的汇率；缺少可靠估值或汇率的数据不能直接相加。借款额度、未结算入账、重复计算的理财资金不计入。演示入账参与规则与正式规则分别配置。

## 3. 权益边界（待确认）

所有会员均保留转账、银行卡安全管理、电子账单、助手和转人工等基础功能。升级权益优先采用能够在现有系统核验和结算的卡面选择、制卡费及换卡费优惠。

费用减免的次数、额度、有效期和是否包含邮费需逐档配置，展示已使用及剩余权益；申卡前由后端计算实际报价，成功办理后消耗权益。前端显示等级不等于已经获得减免。

现有“专属客户经理、机场贵宾厅、旅行险、手续费全免”等文案不能直接作为新会员权益上线；只有真实接入并验证后才展示。升级不改变风控、风险测评、支付确认或实际转账限额。

## 4. 页面组织（建议，未实现）

银行卡页保留两个卡位，分别展示 Visa、银联；未持有时在对应位置申请，已持有时提供管理、锁卡、换卡和安全信息操作。历史卡放进独立历史列表。

产品名称统一为“招财猫 Visa 借记卡”和“招财猫银联借记卡”。不同网络保持不同主色与组织标识，会员等级以徽章和细节呈现。旧交易、费用回单和发卡记录保留当时的产品名称。

“会员与订阅”改为“会员与权益”，展示等级、评定资产、升级进度、有效期、可用权益及使用记录。个人资料与银行卡页均读取同一个会员结果，不再保存互相矛盾的等级文案。

会员升级立即更新数字展示；已寄出的实体卡保持原样。需要新卡面时由用户主动申请同组织换卡，不自动换号、收费或寄卡。

## 5. 当前实现差距与迁移

当前默认档案包含两张 Visa 和一张银联；申卡接口没有按卡组织限制数量。用户资料中的“金卡会员”与会员页的普通、付费套餐也不是同一数据来源，套餐权益尚未接通结算。

实施时调整新演示档案为每组织最多一张。服务器存量重复卡先列出待处理清单、阻止继续增发，不静默删除或作废；需要确认保留卡后再迁移，余额、冻结、流水和历史卡记录全部保留。旧会员订阅保留原始记录，不触发自动扣费或将其伪装成资产达标等级。

## 6. 实施与验收

数量限制由后端按客户和卡组织校验，并覆盖并发、幂等、网页、App 与 Agent 入口；前端禁用重复申请仅用于提示。换卡按同组织处理，重复提交不重复扣费、发卡或消耗权益。

落地时同一提交更新账户模型、银行卡及会员接口说明、知识库、技能和断言；回归现有资金、锁卡、换卡、确认与取消流程。会员需要独立的日终快照、评定记录和权益使用记录，不能只修改前端标签。
