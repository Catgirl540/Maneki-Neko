Sheet 2 · 总览页

总览页界面稿（/dashboard · 桌面 1280）

首版四个模块：资产与多币种余额、最近交易 Feed、现金流与消费趋势、快捷操作与待办。不内嵌助手聊天框；助手仅经侧栏独立入口出现。

图 2-1 · 总览 /dashboard桌面 1280 · 侧栏高亮「总览」演示数据
  • 三张币种卡是同一资金账户 6222 **** 0001 的余额分区，不是三个账户；账号全页只出现一次，卡号与账号不混用。
  • 总资产与会员评级同口径：仅储蓄资金账户折人民币，不含理财与授信；不承诺收益，走势与评级数字均为演示数据。
  • 交易 Feed 按日期分组，收入绿色加号、支出中性色减号，跨币种各列原币；账户内换汇标注「不计入支出」。
  • 待办来自工资计划、银行卡状态、在途转账与自动扣款合约四类真实数据源，每条带状态点与跳转入口。
Sheet 3 · 智能助手页

智能助手页界面稿（/assistant · 桌面 1280）

三栏布局：会话列表、对话区、本次会话能力。能力选择按会话隔离，回应「旧版能力选择跨会话保留并混答」的测试报告缺陷。

图 3-1 · 智能助手 /assistant桌面 1280 · 侧栏高亮「智能助手」演示数据
  • 能力芯片与 app/src/components/layout/services.ts 的 smartServices 同名同序；当前会话已选高亮，未选灰显。
  • 助手回答中「页面实时数据」与「一般知识」用不同卡片样式区分，报价类结论必须落在实时数据块内。
  • 每条回答带来源标注（页面实时数据 / 知识库 / 用户提供）与「不能代办转账、需支付密码确认」免责。
  • 业务页 docked 助手面板不在本页范围，保持不变。
Sheet 4 · 设计说明

模块映射与开放问题

总览各模块借鉴的信息架构来源与对应数据接口；开放问题待用户确认后进入实现稿。

模块借鉴的信息架构对应招财猫数据来源 / 接口
总资产卡Mercury 账户总览汇总（单账户、折本币）资产快照与余额：GET /api/accounts 返回的 Account 折人民币合计
会员等级条Wise / Revolut 任务与状态分组会员评级：上月日均储蓄资产折人民币（白银 / 黄金 / 铂金 / 钻石）
币种余额卡Wise / Revolut 多币种余额卡getBalance 币种分区（currencyBalances，共享同一 accountNo）
近 30 天现金流Mercury 分析与流水关联cashflow 统计接口（分币种记账，账户内换汇不计收支）
本月消费分类Mercury 分类分析spending 统计与系统自动分类（其他类固定灰显）
快捷操作Wise / Revolut 快捷操作入口转账 / 换汇 / 收款与转入 / 申请银行卡 / 账单导出的既有路由入口
待办列表Revolut 任务状态分组salary plan、cards（寄送 / 到期）、inflight 转账（可撤回窗口）、autodebits 合约
最近交易 FeedStarling 交易 Feed 阅读秩序（日期分组、收支分色）listTransactions（跨币种各列原币）
智能助手三栏现有助手工作台演化为独立页会话与能力：smartServices（services.ts），能力按会话隔离

待用户确认的开放问题

  1. 总览是否需要在首版之后显示理财持仓摘要？当前口径严格只含储蓄资金账户。
  2. 会员等级条是否常驻总览首行，还是并入「个人与安全 · 会员等级」页内展示？
  3. 助手除侧栏独立入口外，是否需要在业务页保留悬浮唤起按钮（docked 面板本稿维持不变）？
  4. 现金流默认展示近 30 天，是否需要提供自然月切换与币种筛选？
  5. 移动端不在本稿范围，总览与助手的移动适配是否另出草稿评审？
