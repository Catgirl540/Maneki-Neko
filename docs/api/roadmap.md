# 待完成业务与远期接口

已有页面和 HTTP 路由不等于完整业务。当前能力及限制见 [接口索引](./README.md#当前实现范围)。

## 新增演示域尚缺的实现

- 共用基础：旧档案增量迁移、新用户独立初始化、运行时参数校验、写操作验密、持久化错误处理和必要的重复提交保护。
- 存钱计划：目标转入/取出、消费凑整触发、周期归集、打卡统计、奖励入账。
- 工资与备用金：工资代发与入账对账、备用金支用、计息、还款；目前仅保存设置和开关。
- 借款与分期：审批、还款计划执行、消费分期资格及重复办理校验、还款与逾期处理。
- 现金管理与定投：账户绑定、开户与适当性前置校验、周期调度、买入扣款、份额与收益计算。
- 保险：核保与条款确认、承保对接、续期、退保及理赔；目前只有模拟扣费和保单记录。
- 会员与邀请：扣费续订、有效期和权益执行、邀请关系归因、奖励发放。
- 身份与卡安全：图片采集、OCR/活体核验、资料脱敏、卡扩展字段持久化、一次性卡支付授权及失效机制。
- 账户内换汇：服务端锁价与确认条件绑定、金额/币种校验、原子扣入账。

## 2026-10-13 新增域代码审查（问题仍待修复）

审查基线：主分支 `e0a12e7` 中 PR #5 的新增网页功能。以下八项用内存银行或临时 SQLite + 本地 HTTP 服务复现；没有修改正式客户数据。本文档修正不代表业务代码已修复。

1. **P1 · 升级会重建旧账户数据。** `MOCK_SCHEMA` 升为 17，但 `loadDb()` 遇到旧版本仍调用 `seed()` 并持久化。临时旧版档案余额 4,321 分被改成 128,464,055 分；非当前旧档案也未补齐新增字段。应增量迁移全部客户档案，保留身份、余额与流水，禁止用演示种子替换持久数据。依据：[db.ts](../../app/src/api/mock/db.ts#L80)、[loadDb](../../app/src/api/mock/db.ts#L1900)。

2. **P1 · 新用户继承其他客户的新增档案。** 注册从当前档案 `structuredClone`，仅清理旧字段；新加的保单、借款、邀请、会员、存钱及虚拟卡等未初始化。新用户 API 能读到前一客户的保单与邀请数据，一次性卡号/CVV 还会随新档案保存。应按新用户独立构造这些域，不能复制当前客户。依据：[register](../../app/src/api/mock/index.ts#L652)。

3. **P1 · 字符串借款金额污染余额。** `amount: "100000"` 可通过金额区间比较，然后被传给 `applyBalance` 做 `+=`，余额由数字变成拼接字符串；HTTP 返回 200，错误值随档案保存。应在任何写操作前验证金额为正的安全整数，同时验证期数类型。依据：[applyLoan](../../app/src/api/mock/index.ts#L2418)、[入账](../../app/src/api/mock/index.ts#L2451)。

4. **P1 · 新增资金操作可省略支付密码。** 借款、投保和定投使用 `if (req.paymentPassword)` 才验密；HTTP 调用省略字段即可绕过页面密码框。已复现借款到账和投保扣费均返回 200。应在服务端强制认证，并将请求类型与页面要求对齐。依据：[借款](../../app/src/api/mock/index.ts#L2431)、[投保](../../app/src/api/mock/index.ts#L2569)、[定投](../../app/src/api/mock/index.ts#L2540)。

5. **P2 · 卡扩展设置保存后丢失。** PATCH 会回显 `paymentEnabled=false` 与渠道限额，但 SQLite `saveCards`/`hydrate` 未覆盖这些新字段；下一次 GET 就消失。应完整持久化并实现授权校验后再将其作为有效控制。依据：[新增设置类型](../../app/src/api/types.ts#L1179)、[卡恢复](../../server/database.mjs#L249)。

6. **P2 · 换汇确认未绑定报价。** 页面显示三十秒锁价，提交却不含报价编号、汇率或确认条件，银行重新计算。内存验证改变参考汇率后，同一笔确认的到账额从 13,925 分变为 12,659 分，未被拒绝。应在银行端绑定报价及截止时间，价格变化时重新确认。依据：[页面提交](../../app/src/pages/ExchangePage.tsx#L89)、[重新计算](../../app/src/api/mock/index.ts#L2088)。

7. **P2 · 定投可接受不存在的账户且绕过开户前置。** 新注册用户未开理财账户、未测评，传 `accountId: "not-owned"` 仍返回 200；账户字段未核对或保存。应先校验开户/测评、扣款账户归属与周期，再保存可执行计划。依据：[createInvestPlan](../../app/src/api/mock/index.ts#L2532)。

8. **P2 · 同一笔支出可重复分期。** 对同一交易连续两次提交分期均返回 200，产生两份计划；也未限制为成功消费，手续费、转账和失败支出都可能入选。应限制交易类别与状态，建立交易和有效分期计划的唯一关联。依据：[convertToInstallment](../../app/src/api/mock/index.ts#L2481)。

OCR 固定资料、活体直接通过、自动归集/定投/续费等缺少执行任务已按占位或待完成能力标注，不重复当作已交付业务。
