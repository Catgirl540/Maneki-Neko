# 运维监控（本地第一版）

工作人员端新增 `/operations`。员工角色新增 `ops`，接口契约 v1.3。
使用独立运维账号登录后进入运维监控；客服与主管保持原业务菜单。

## 本地查看

工作人员端以 `VITE_USE_MOCK=false` 连接银行后端。在 <http://127.0.0.1:5181/login> 登录：

- 员工姓名：`运维人员`
- 演示密码：`123456`

首次建运维账号可通过 `BANK_OPS_PASSWORD` 设置密码；已经存在的账号不会被启动环境变量重置。
银行后端启动时增量迁移旧员工表的角色约束，保留原员工身份和密码摘要。

## 查询接口

`GET /staff-api/ops/overview`，银行后端逐请求校验 `ops` 角色。
未登录返回401，其他员工角色返回403，非GET方法返回405。
运维账号不能调用客户查询、代客办理、工单、资金处置、业务审计及阈值修改接口。

响应包含：

- 服务：银行后端、SQLite可读性、客户端网页、工作人员端网页、AI健康接口。
- 错误：近24小时计数，以及脱敏的运行事件，最多显示100条、持久化保留1000条。
- 备份：本地快照的时间、大小及SQLite结构/完整性校验；无快照明确返回缺失。
- 版本：启动时Git提交、工作区改动状态、Node版本、环境和进程启动时间。

## 运行配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `BANK_CLIENT_HEALTH_URL` | `http://127.0.0.1:5180/` | 客户端网页可访问性检查 |
| `BANK_STAFF_HEALTH_URL` | `http://127.0.0.1:5181/` | 工作人员端网页可访问性检查 |
| `BANK_AGENT_HEALTH_URL` | `http://127.0.0.1:8788/agent-api/health` | AI服务响应必须包含 `ok: true` |
| `BANK_BACKUP_DIR` | `server/data/backups` | 只读取 `.sqlite` / `.db` 普通文件，最多10个 |

网页检查只代表HTTP可访问，数据库检查只代表当前连接可读取，不替代业务端到端检查。
探测并行执行，每项最多2秒。页面手动刷新；请求失败保留上次结果并显示错误和原检查时间。

## 数据与范围

`operations_events` 保存服务启动、HTTP 5xx及扫账异常的类别/状态码。
不保存请求正文、查询参数、客户身份、密码、验证码、令牌、原始错误正文或堆栈。
启用前的错误不回填，记录跨重启保留；近24小时计数只覆盖已采集事件。

备份状态区分缺失、无效、超过24小时和有效。不创建或修改快照，不下载快照、不执行恢复。
“有效”仅表示文件检查通过，恢复演练、发布记录、重启、回滚和告警通知尚未接入。
该监控页面提供只读状态；运维助手的原生文件、命令及风险确认能力见 [工作人员 Agent](staff-agent.md#运维原生-dsh-与-clef-flash)。

## 验证

- `npm run build --prefix staff`：类型检查及构建。
- `node tools/check-operations.mjs`：旧员工迁移、角色隔离、服务探测、备份状态、日志脱敏、重启持久化及HTTP5xx采集；独立临时SQLite。
- `CHROME_PATH` 指向本机Chrome后运行 `node tools/check-operations-ui.mjs`：真实页面、菜单隔离、路由守卫及登录退出。
