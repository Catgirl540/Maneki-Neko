# 后端内存修复与本地容量验证

本次只修改和验证本地代码，未连接或部署生产服务器。2026-10-22 的外部审计报告用于确定排查方向；昨晚实际部署版本和内核 OOM 日志仍需单独核对。

## 处理机制

- HTTP 银行入口使用 `profileProjection: 'scoped'`：事务只加载当前及本次业务实际查询的客户，不再解密全体客户和流水，也不在提交后全库 hydrate。
- 同步业务层使用对象存储接口，避免客户集合反复 JSON stringify/parse。事务结束释放档案缓存；下一事务在 PostgreSQL advisory lock 之后重新加载，保留跨进程隔离。
- 按客户指纹跳过未变化档案；按流水指纹跳过未变化历史行。新流水前插使用更小的 ordinal，不通过更新全部旧流水来移动顺序。金融身份校验、不可删除历史和借贷平衡约束保留。
- 客户索引只增量更新本次客户，换手机号只移除本人旧绑定，不能用部分内存投影替换全库绑定。
- scoped 写入必须在数据库 unit of work 内执行；事务外的写入直接拒绝，不能悄悄进入下一客户的 staged 缓存。
- 收款账号/FPS/客户查询通过 SQL 定位，银行卡候选先核对加密 PAN，再加载匹配客户。员工客户搜索使用 SQL 摘要，不载入全部档案。
- sandbox 扫账按待处理客户分页，每客户单独进入原事务队列；无 pending 流水时不解密全库。现有防重复排队保留。live 模式仍不启用模拟结算。
- 原始 localStorage 全量接口保留给显式离线导入/兼容夹具，不作为 HTTP 运行时接口。单个客户的历史流水仍按该客户档案加载，本次没有宣称实现任意单客户历史规模下的恒定内存。

## Agent 缓存

累计正文快照在内存回放中只保留同消息最新版本，同时按 256 条和约 1MiB 限制回放缓存。实时 SSE 继续发送正文；累计快照最多每秒持久化一次，最终正文、工具结果和业务确认事件仍逐条持久化。突然中断时，网页回放的中间正文最多落后一个检查点；不影响已提交银行账务。

缓存最多 200 会话/进程、50 会话/人，闲置 15 分钟且无请求、订阅和运行任务时回收。SQL 历史不随缓存删除。启动只在 SQL 标记中断，不全量解密恢复会话；本人重新打开时按归属加载。恢复事件先在 SQL 侧按加密字节总量筛选，避免一次读取 256 个巨型快照。

## 复现和验收

`tools/backend-memory-lab/` 提供独立 Linux/WSL 实验脚本：

1. `setup-linux.sh`：创建专用 40GiB ext4 数据盘和 PostgreSQL 16 测试实例（仅 `127.0.0.1:55433`）。
2. `test-linux.sh` / `test-local.mjs`：仅向四个显式命名的本地专用测试库运行门禁，不复用生产连接和模型密钥。
3. `seed.mjs`：生成合成客户和真实加密格式的规范化流水；默认 504 户、每户 200 笔，共 100,800 笔。不是“每户十万笔”。
4. `prepare-linux.sh`：克隆合成库，用于相同数据下的 before/live/demo 对比。before 库仅调整迁移版本标记以运行修复前快照，新增索引保留，未移除账务保护。
5. `copy-runtime.py`：将运行时复制到实验盘并修正本机生成的 Windows 路径；不改用户原有 DSH 配置。
6. `run-linux.sh before|fixed`：整个进程树共享 cgroup v2 的 2 个 CPU、4GiB 内存和零 swap，额外预留 512MiB 模拟操作系统占用。固定环境包含 PostgreSQL、两个银行、四个 Agent、真实 DSH 子进程和 Nginx，模型上游使用本机协议夹具。

运行前须安装 Node 24、PostgreSQL 16、Nginx 和对应平台的 DSH 原生依赖。每次只能有一个集成测试或容量实验使用同组测试数据库。实验结果、随机会话凭据和修复前源码快照保存在忽略目录 `.generated/backend-memory-lab/`；不可提交这些连接/会话文件。

WSL/cgroup 能验证资源预算和进程峰值，不能等同云服务器 CPU、磁盘吞吐、网络或长时间真实模型负载。最终数字以本次结果报告为准；被跳过的测试必须单独说明。

本轮实际采样、通过项与限制见 [本地容量验收结果](backend-memory-local-results-20261022.md)。

## 部署准备

数据库结构版本为 `2026102201`，增加 pending 客户和活动银行卡尾号索引。实际部署前须先由数据库所有者运行 `server/bootstrap-postgres.mjs`，应用仍使用受限角色和 `BANK_AUTO_MIGRATE=false`。不能重建在线客户数据或更换原加密密钥。

先对账与备份，再发布同版 server/shared/bridge 文件；服务树须有总预算，Node 堆限制不等于整个服务 RSS 上限。systemd 的 `MemoryMax` 包含所属 cgroup 中的 DSH 子进程。保留旧发布版本和原生日志，回退不回滚客户账务。
