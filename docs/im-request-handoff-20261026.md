# 微信银行请求恢复与确认门户修复

2026-10-26。用户报告：微信的基本查询要求打开链接，进入正常网页后却没有本次请求或确认信息。截图是 `#code=` 登录恢复链接，银行请求尚未启动；同时复核了真正的 `#session=` 确认页。

## 根因与修复

1. 原登录门禁只返回绑定码并丢弃用户原文，登录/绑定成功后不会出现该请求。现在暂存最长 4000 字、非敏感的本次文字请求，认证本人后显示原文；恢复连接与继续办理为独立动作。没有明确点击“继续这次请求”，不会启动银行工具。
2. 确认门户原先只从 `events?after=0` 回放历史，没有先读取服务端当前有效的确认/问题快照。现在先读取无游标的当前快照，另取历史回复；不从历史重建已失效授权。保留快照游标读取随后发生的事件，防止加载期间漏掉新卡。
3. 同页更换微信链接原先未重新处理 hash；刷新或旧链接过期也可能只剩普通连接界面。现在处理新链接、自动定位唯一的本人在线私聊、显示明确失效说明；有有效卡时滚动到确认区，长聊天不会埋掉确认卡。
4. 主网页绑定区显示原请求及独立继续入口，本人的未消费待续请求随连接列表恢复，刷新不丢入口。原业务门户可借用本标签页已有的客户登录，经服务端验证后打开本人会话；不写新的浏览器令牌，不用于工作人员或运维恢复。
5. 同一客户同一私聊仅重登银行时保留提醒绑定版本，避免原提醒被误停。真正解绑、换人、换私聊仍使原授权失效。

## 授权与隔离

`POST /agent-api/im/continue` 需要已登录本人、`confirmed:true`、32 字符随机凭证，并复核当前路由、绑定版本、银行会话和登录状态。凭证在启动前一次消费；网络重试不能重复启动。直接回微信发送新银行指令会使旧待续请求失效。继续只重新准备请求，资金操作仍需要原确认和支付校验，不恢复旧金融授权。

原请求和继续凭证只在内存保留至绑定码过期（最长十分钟），不写客户资金库、不持久化密码/验证码。解绑、换绑、服务重启后不能恢复；旧链接必须在原微信重发以获取最新入口。提醒专用通道保持微信内直接办理和网页同步。
