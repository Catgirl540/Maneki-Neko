# 客户助手凭据防护

客户助手文字、历史迁入、问题卡答案和已绑定 IM 的输入在交给助手前进行检查。明确的密码赋值表达由规则直接拒绝；其余文字由本机决策服务判断。模型不可用、返回不完整或判定不确定时拒绝本次请求。防护不会识别用户未表达的真实密码，也不能保证识别所有变体；正式启用前需用合成数据校准阈值并评估漏报和误报。

## 配置主模型与备用模型

设置 `LUCKYCAT_CREDENTIAL_GUARD_ENDPOINTS` 为 JSON 数组，按优先顺序列出本机 System One 兼容决策服务的完整 URL 与模型名：

```json
[
  {"url":"http://127.0.0.1:9001/v1/systemone","model":"span-02"},
  {"url":"http://127.0.0.1:9002/v1/systemone","model":"backup-decision-model"}
]
```

示例端口和模型名仅为占位；需独立安装并启动兼容服务，备用服务也必须支持同样的 `choice` 请求和概率响应。代码不下载模型、不启动推理服务。只允许 HTTP 本机回环地址，禁止远程地址与重定向，避免把未识别的秘密发给第三方。端点最多 5 个，每个请求的超时为 1.2 秒；只有网络故障、超时或无效响应才尝试下一项，明确风险或不确定结果直接拒绝。`safe` 概率阈值 0.5 为初始配置，未经校准，不代表测得的安全水平。

未配置端点时，客户助手的所有非空文字会因安全检查不可用而拒绝，属于故障关闭；请先准备服务再部署。当前未检查图片和音频中的凭据，客户助手暂不接受图片，也不提供语音转文字。其他入口（例如人工客服独立消息、已发生的外部 IM 平台传输、员工助手）不在此防护范围内。支付密码仍只应通过现有确认卡发送至银行验证接口，不应交给决策模型。

运行离线测试：`node --test framework/bridge/credential-guard.test.mjs`。测试使用本地模拟响应，不调用真实模型。生产部署前还需在隔离环境测试服务兼容性、中文样本、超时、并发、浏览器操作、历史迁入和 IM 路径，并确认代理及推理服务不记录原文。
