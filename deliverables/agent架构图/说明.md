# Agent 架构图说明

`agent架构图.drawio` 为原生可编辑的 draw.io 文件，包含「架构总览」和「工具确认与执行链路」两页。SVG 与 PNG 为预览导出。

图基于 2026-11-02 当前仓库代码，表示代码结构与能力边界，不代表所有可选通道在当前部署均已启用。

## 阅读口径

- 三个角色分别运行独立 Bridge 和 Harness 子进程，复用同一实现模式。转账、理财等是 skills / tools；bank-agent、staff-agent 是可信业务适配层。
- 客户和客服 / 主管使用 read-only 主机沙箱；业务写入通过银行 HTTP 服务执行。运维具有独立的 workspace-write 原生工具分支。
- AI PostgreSQL 保存会话归属和加密回放事件；模型上下文及附件还依赖 Harness 本地目录。AI 存储角色与银行资金表权限隔离。
- RAG 使用生成的本地 corpus 与进程内向量；图中没有独立向量数据库。向量不可用时降级关键词检索。
- 普通需要授权的业务经确认卡；有效 IM 绑定内的白名单只读查询有本轮一次授权特例。技能或模型文字不等于金融授权。
- 银行系统当前为演示 / 开发平台，真实合作银行通道尚未接入；业务服务返回的回执和状态为图中执行结果来源。

## 主要依据

- `framework/bridge/demo-server.mjs`：HTTP、SSE、DeepSeekHarness、内部通道、确认、语音和 IM 装配。
- `framework/bridge/staff-server.mjs`、`framework/bridge/ops-server.mjs`：角色入口与端口。
- `framework/profiles/luckycat/cordis.patch.yml`、`framework/profiles/staff/cordis.patch.yml`、`framework/scripts/bootstrap-staff.mjs`：模型、插件、角色白名单与沙箱。
- `framework/packages/consent/src/index.ts`、`framework/packages/hardening/src/index.ts`：执行前审批与工具守卫。
- `framework/packages/bank-demo/src/http-tools.ts`、`framework/bridge/bank-agent.mjs`、`framework/bridge/staff-agent.mjs`：HTTP 工具、可信字段、参数绑定授权与最终执行。
- `framework/packages/rag/src/index.ts`、`framework/packages/rag/src/retrieve.ts`、`framework/knowledge/README.md`：知识库、混合检索与降级。
- `framework/packages/skills/cordis.patch.yml`、`framework/skills/`、`framework/bridge/service-skills.mjs`：业务技能与功能入口。
- `framework/bridge/session-store.mjs`、`docs/bank-ai-session-postgresql.md`：会话加密、namespace、单实例锁及模型上下文恢复边界。
- `framework/bridge/ops-gate.mjs`、`framework/bridge/clef-reviewer.mjs`、`framework/packages/ops-native/`：运维风险决策、授权与原生工具。
- `docs/api/im-agent.md`、`docs/api/staff-im.md`：IM 身份绑定及只读查询授权。
