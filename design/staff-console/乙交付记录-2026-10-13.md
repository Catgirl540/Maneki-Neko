## 一、做了什么

按分工清单 §1（B = 客户查询 / 代客办理 / 审计日志），补齐三块的前后端实现。

### 1. 客户查询（P0）
- 后端 `GET /staff-api/customers?keyword=`：跨档案按姓名/手机号/客户号搜索，返回脱敏摘要；每次查询落审计 `customer.search`。
- 后端 `GET /staff-api/customers/:id/profile?reason=`：客户 360（账户/卡片/最近流水）；**事由必填**；敏感资料访问与返回在**同一接口内原子落 `customer_access_logs` + 审计 `customer.profile.view`**（不变量 6/10）。
- 前端 `staff/src/pages/customers/`：搜索 → 摘要列表（含风险标签、手机号脱敏）→ 填事由 → 展开 360。

### 2. 代客办理（P1）
- 后端 `POST /staff-api/customers/:id/actions/:action`：白名单动作 `lockCard / unlockCard / updateCardSettings / patchAutodebit`；高影响动作（解锁/调限额）必须核验通过，核验失败一律拦；落审计 `customer.action.*`。
- **复用客户端业务规则，不复制校验**：经 `demo-bank.mjs` 的 bankHooks 切到客户档案，直接调 mock 的 `setCardLock / updateCardSettings / setAutoDebitEnabled`（锁卡联动 onlinePayment/overseasPayment 一并关，由 mock 自己保证）。
- 前端 `staff/src/pages/actions/`：选客户 → 选动作 → 选目标卡 → 填工单号/核验/事由 → 确认办理。已支持锁卡/解锁/调限额三个卡动作。

### 3. 审计日志（P2 查询页）
- 后端 `GET /staff-api/audit-logs`：沿用甲已接的最小版（仅主管 403，返回 200 条）。
- 前端 `staff/src/pages/audit/`：在最小表格上加操作者/动作关键词/时间窗筛选（前端过滤，与工单中心一致）。

## 四、已知缺口 / 降级（诚实报告，清单 §0.7）

1. **契约缺口（需甲补）**：`CustomerActionRequest` 只有 `ticketId/verificationMethod/verificationResult/reason`，**缺目标字段 `cardId/dailyLimit/autoDebitId/enabled`**。我后端按额外 body 字段读取、前端用本地类型扩展（`ActionsPage.tsx` 内 `type ActionRequest`）绕过，**没有改 contract.ts/types.ts**。建议甲做一次 `[contract]` commit 把目标字段正式加进类型，前端再删本地扩展。
2. **`patchAutodebit` 前端未接通**：后端路由已就绪，但 `CustomerProfile` 契约不含 `autoDebits`，前端无法选代扣目标，故代客页只做了锁卡/解锁/调限额。待契约补 `autoDebits` 后接通。
3. **客户 360 缺「历史工单」**：`CustomerProfile` 契约无 tickets 字段，且工单属甲模块，未实现（可用 `listTickets` + 前端按 customerId 过滤补）。
4. **mock 模式是最小桩**：`performCustomerAction` 在 mock 下仍返回 `{ok:true}`、`searchCustomers` 只按姓名匹配——按清单 Phase 0「mock 最小版」纪律，完整业务只在真后端（`VITE_USE_MOCK=false`）。
5. **风险标签是 demo 级启发式**：只推两条规则（在途转账 / 有锁卡），非完整风控。
6. **审计筛选在前端做**：后端 `audit-logs` 仍是无参返回 200 条，筛选在页面过滤（与工单中心做法一致）。

## 五、演示前怎么用

1. 真后端联调：客户端/员工端都设 `VITE_USE_MOCK=false`。
2. 员工端 `客户查询` 搜「林」或「13800138000」→ 点开填事由看 360。
3. `代客办理` 选林小满 → 锁卡 → 回客户端看那张卡变锁（同一份数据）。
4. 李主管进 `审计日志`，能看到 `customer.search / customer.profile.view / customer.action.lockCard` 留痕。
