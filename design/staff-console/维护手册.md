## 0. 系统一眼

```
server/index.mjs   后端 8080
  ├─ /api/*        客户端通道（app/，5180）
  ├─ /staff-api/*  员工端通道（staff/，5181）
  └─ /agent-api/*  agent 通道（要 X-Agent-Token）

framework/bridge/demo-bank.mjs   真正的银行业务实现（一份数据、一处逻辑）
server/staff-api.mjs             员工端路由 + 审计 + 权限
app/src/api/mock/                银行数据与业务规则的唯一实现（后端 import 它）
staff/src/api/contract.ts        员工端接口面（v1.2），组件只 import { api }
```

**两套前端共用一个后端**，只是路径前缀不同。员工 token 与客户 token 不混用。

`staff/src/api/index.ts` 的切换点：

```ts
VITE_USE_MOCK=true  → 本地写死样例（默认，不需要后端也能看页面）
VITE_USE_MOCK=false → 真后端 /staff-api/*
```

**演示/联调一律 `VITE_USE_MOCK=false`。** mock 的转账是立即到账，挂起→审核→放行整条链只有真后端才有。

## 1. 起停

### 1.1 三个进程，谁先谁后

```bash
# 后端（必须先起）
BANK_PORT=8080 node server/index.mjs

# 客户端
cd app && VITE_USE_MOCK=false VITE_PROXY_TARGET=http://127.0.0.1:8080 npx vite

# 员工端
cd staff && VITE_PROXY_TARGET=http://127.0.0.1:8080 npx vite
```

`staff/.env.local` 写 `VITE_USE_MOCK=false` 即可（**别提交进仓库**）。后端不起，前端会回落到「后端没起」提示，不会白屏。

端口被占用时 Vite 会**自己往上加一**（5180 占了就开 5181），日志里打印的那个才是真的，别照抄文档里的端口号。员工端固定 `server.port = 5181`。

### 1.2 端口被别人占了

```
Error: listen EADDRINUSE: address already in use :::8080
```

```bash
netstat -ano | findstr :8080
```

**不要 `taskkill` 不是你起的进程。** 起自己的实例换端口最省事：

```bash
BANK_PORT=8090 node server/index.mjs
cd app   && VITE_PROXY_TARGET=http://127.0.0.1:8090 npx vite --port 5183
cd staff && VITE_PROXY_TARGET=http://127.0.0.1:8090 npx vite --port 5184
```

### 1.3 后台进程被系统回收了

Windows 内存吃紧时，挂后台的进程会被直接杀掉，**不是崩溃，没有报错可查**。表现为：

- 页面突然连不上 / 接口全 502
- 进程列表里没了

处理：重新起一遍（1.1）。别去查日志，没有日志可查。

要关闭该回收行为，以 `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1` 启动 Claude Code（对 shell 命令设置无效）。

### 1.4 一分钟自检

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5180/          # 客户端
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5181/          # 员工端
```

三个都是 200 才算起来。注意 5181 可能只监听 IPv6，用 `localhost` 而不是 `127.0.0.1`。

## 2. 排障（按症状查）

### 2.1 「转了账，钱被吞了」——单据永远挂在处理中

**认**：流水 `status = 'pending'` 且**没有** `pendingReason`，或 `pendingReason` 不是 `inflight`，过了十几秒还是 `pending`。余额已经扣了。

**因**：普通外行转账走「模拟清算」，钱当场扣、单据先挂 `pending`，靠扫账翻 `success`。历史上这段路**没有调度器**，单据就永远挂着（2026-10-12 事故，commit `bb93a90` 修）。

**处置**：
1. 重启后端。扫账里的兜底逻辑会把**所有非 `inflight` 的 pending** 结清，孤儿单也能捞起来。
2. 捞起来后核对余额：应恰好等于转账金额，不多不少。
3. 如果重启后还不结清，说明 `tickHolds()` 没在跑——查 `framework/bridge/demo-bank.mjs` 的 `holdTimer`。

**区分**：`pendingReason` 只有两个值，别混——

| 值 | 含义 | 谁来结 |
|---|---|---|
| `inflight` | 大额延迟到账窗口 | 窗口到点自动到账 / 员工处置 |
| `clearing` | 模拟清算（几秒） | 扫账 3 秒后翻 `success` |
| *（无）* | 老数据 / 孤儿单 | 扫账兜底结清 |

### 2.2 「付款成功了，收款方没收到钱」

**认**：付款流水 `status = 'success'`，审批单 `settled / succeeded`，但**收款方余额增量为 0、入账流水 0 条**。

**因**：`activateDb()` 切档案时顺手 `persist()`，而它写的是调用方递进来的对象。定时扫账跨档案遍历时，收款方在扫描开始时就被快照了一份；处理付款方时新余额写盘了，但遍历数组里那只是**旧对象**。旧对象再写回，`saveLedger()` 删表重建，收款方刚入账的行被整段抹掉（2026-10-12 issue #3，commit `c1d6325` 修）。

**处置**：
1. 确认 `activateDb()` 里是 `cache = latestStoredProfile(next.user.id) ?? next`，**不是** `cache = next`。改回旧实现立刻复发。
2. 补账只能手工：从付款流水反查金额，再走客户端正常转账补一笔。**别直接 `UPDATE bank_*`**（见 §3.2 红线）。
3. 回归用例：`node tools/transfer-hold-smoke.mjs` 场景 H「收款方余额如数入账」。它能在 bug 存在时红（收款 0 元、流水空）。

### 2.3 员工登录失败 `BAD_CREDENTIALS`

**认**：账号密码明明对，就是登不进。

**因**：用 `curl` 发含中文的请求体会被 GBK 污染，「王小明」到了服务端变成乱码。

**处置**：测试一律用 Node `fetch`，别用 curl。见 `tools/transfer-hold-smoke.mjs` 顶部注释。

### 2.4 阈值改了不生效

**认**：员工端改了延迟到账阈值，转账该进窗口的还是不进。

**因**：阈值存在 `staff_settings` 表，**每笔转账现读**，改完立刻生效、不用重启。如果不生效，多半是改的是**环境变量** `BANK_TRANSFER_REVIEW_CENTS`——它只在**第一次建库**时当种子值写进去，之后就再也不管了。

**处置**：

```bash
node -e "const{DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('server/data/bank.sqlite');
console.log(db.prepare('SELECT key,value FROM staff_settings').all());db.close()"
```

看 `transfer_review_cents` 的实际值。要改就走员工端（主管身份），别改环境变量。

上限 `90000000` 分 = ¥900,000，超了会被 400 拒。

**阈值与窗口是两回事**：阈值决定进不进窗口（每笔现读，员工端可改）；窗口决定在途多久（`BANK_TRANSFER_HOLD_SECONDS`，启动时读定，改了要重启）。

### 2.5 重启后「在途指令」不见了

**认**：重启后，之前挂着的延迟到账转账找不到了。

**因**：`holdUntil` / `heldRequest` 不在 `bank_transactions` 表里（`saveLedger` 不写这两列），它们存在 `app_storage` 的 JSON 里（key `luckycat.mock.db` / `luckycat.mock.user-profiles.v1`）。**JSON 才是权威，`bank_*` 只是查询用的投影。**

**处置**：别指望从 `bank_transactions` 反查在途状态。权威数据在 `app_storage`，查 JSON。

### 2.6 员工端查不到客户端的用户

**认**：客户查询搜出来是空的，或者干脆整页没数据。

**分三类，别一上来就怀疑数据丢了**：

| 现象 | 真因 | 处置 |
|---|---|---|
| 搜「138****8000」为空 | 搜索只匹配明文号 | 已修：`searchCustomers` 的靶子含脱敏号与去星号片段。改回只搜 `${name} ${phone} ${id}` 会复发 |
| 整页没数据 | 员工端还挂在 mock，或后端没起 | 查 `staff/.env.local` 的 `VITE_USE_MOCK`；查 8080 |
| 队友搜得到、你搜不到 | 各人本地 SQLite 独立 | 演示机的数据要自己灌（`reset-demo` 后自己做几笔） |

明文号、脱敏号、去星号片段、姓名、客户号现在都能命中（2026-10-14 修）。

### 2.7 处置中心点开单号，页面变透明

**认**：点处置中心的单号，右侧抽屉没有实心底色，整页像蒙了层灰。

**因**：抽屉背景写了 `bg-[var(--color-paper-deep)]`，而这个 token 在 `tokens.css` 里**不存在**，背景直接穿透。

**处置**：改回 `bg-[var(--color-surface)]`，并把结构对齐 `TicketDrawer`（独立遮罩 `flex-1 bg-black/20` + 右侧面板 `w-[480px] border-l`）。**新增 UI 一律引 `tokens.css` 里已有的变量**，写错 token 名不会报错、只会静默穿透——这是本项目最容易犯的一类视觉 bug。

### 2.8 拦截之后显示「执行失败」，像拦截坏了

**认**：主管点了拦截，处置状态是「已拦截」，但资金执行列标红显示「执行失败」。

**这不是 bug，是措辞错了。** §9.4 的语义：拦截后 `executionStatus = 'failed'` 表示**指令从未执行**，不是执行出错。标红「执行失败」会被误读成拦截本身失败（2026-10-14 修）。

**处置**：执行列对 `intercepted` / `recalled` 显示中性文案「未执行（已拦截）」「未执行（用户已撤销）」。真正要标红的只有一种组合：`status='settled'` **且** `executionStatus='failed'`（窗口已收口但执行出错）。

### 2.9 点「拦截」弹「操作失败」

**认**：客服身份点拦截/立即到账/通过/驳回，报错。

**因**：`POST /staff-api/approvals/:id/decide` **只允许主管**（清单 §5），客服吃 403 `FORBIDDEN`。前端原本对所有角色都渲染按钮，客服点了就只看到一句「操作失败」。

**处置**：非主管不渲染处置按钮，只显示「处置仅主管可执行」+ 当前登录身份（2026-10-14 修）。**前端藏按钮不等于后端不设防**——后端 403 必须仍然真的 403（上线自查项）。

## 3. 数据维护

### 3.1 演示数据归零

```bash
node tools/reset-demo.mjs            # 归零
node tools/reset-demo.mjs --dry-run  # 只打印要做什么
```

会做：删掉 `server/data/bank.sqlite`（下次启动自动长出林小满等演示档案）+ 重建员工端六张表 + 撒回演示种子。

**必须先停 server。** Windows 不让删被占用的文件：

```
EPERM ... bank.sqlite
```

### 3.2 红线（违反会静默毁数据）

- **绝不直接 `UPDATE` / `DELETE` `bank_transactions` 或 `bank_accounts`。** `saveLedger()` 每次落库是**删表重建**该 owner 的行，手改的会被下一次落库整段抹掉。
- 一切资金变动走 `submitTransfer` + `persist()`。
- 绝不直接改 `app_storage` 的 JSON——那是权威数据，改坏了没法回滚。

### 3.3 两层存储，别找错地方

| 存哪 | 内容 | 权威性 |
|---|---|---|
| `app_storage`（JSON） | 客户档案、余额、流水、**`holdUntil` / `heldRequest`** | **权威** |
| `bank_accounts` / `bank_transactions` | 查询投影，员工端/agent 查流水用 | 只读，每落库重建 |
| `staff_*` 表 | 员工账号、工单、审批、审计、阈值 | 权威 |

### 3.4 演示账号

| 角色 | 账号 | 密码 | 能干什么 |
|---|---|---|---|
| 客服 `csr` | 王小明 | 123456 | 工单、客户查询、代客办理；**不能**处置审批单、看审计 |
| 主管 `supervisor` | 李主管 | 123456 | 全部，含处置、改阈值、审计 |
| 客户 | 林小满 13800138000 | 123456 | 客户端 |
| 客户 | 陈嘉禾 13600136000 | 123456 | 客户端 |

员工 token（12h）与客户 token 不混用。**改阈值 / 处置审批单要主管身份。**

## 6. GitHub 协作纪律

仓库：`https://github.com/Catgirl540/Maneki-Neko`

### 6.1 动手前先看未合并分支

多人同仓，最容易白做工的是**改了别人正在改的文件**。开新活之前：

```bash
git fetch origin
git log --oneline origin/main..origin/<队友分支> --stat
```

已知撞车热点（2026-10-14 时点）：

| 文件 | 谁在动 | 纪律 |
|---|---|---|
| `app/src/pages/TransferPage.tsx` 等转账状态闭环 | PR #6 | 合并前别动 |
| `staff/src/**/ChatWorkspace*`、agent 入口 | PR #10 | 动 agent 前先定基线 |
| `staff/src/api/contract.ts` / `types.ts` | 契约专用 | 走 §6.2，别顺手改 |

### 6.2 契约变更单独走

`staff/src/api/contract.ts` 是员工端唯一接口面（当前 v1.2）。改签名/字段/错误码：

1. **单独 commit**，标题带 `[contract]` 前缀；
2. **版本号 +1**，在文件头注释写清改了什么、为什么；
3. **群里广播**；
4. mock 与 http 两套实现同时改（`check-contract` 会比对方法集合，漏一个当场红）。

禁止在功能 commit 里顺手改契约。

### 6.3 提交与 PR

```bash
git checkout -b fix/<症状>        # 不要直接往 main 提
# ...改动...
node tools/transfer-hold-smoke.mjs && node tools/staff-customers-smoke.mjs   # 必须全绿
git add <只加自己改的文件>
git commit
```

- **只暂存自己改的文件**，工作区里常有别人未提交的半成品，`git add .` 会把别人的东西一起带走。
- commit message 写清**症状 + 根因 + 怎么验的**，别只写「fix bug」。
- PR 描述末尾附：

  ```
  🤖 Generated with [Claude Code](https://claude.com/claude-code)
  ```

- commit message 末尾附：

  ```
  Co-Authored-By: Claude Code <noreply@anthropic.com>
  ```

### 6.4 改员工端 UI 的三条硬规矩

1. **颜色只引 `staff/src/styles/tokens.css` 里已有的变量**。写错 token 名不报错、只静默穿透（见 §2.7）。
2. **抽屉结构对齐 `TicketDrawer`**：`fixed inset-0` + `flex-1 bg-black/20` 遮罩 + `w-[480px] border-l bg-[var(--color-surface)]` 面板。别自创结构。
3. **角色门禁前后端都做**：前端隐藏按钮是体验，后端 403 是安全，缺一不可。
