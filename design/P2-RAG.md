# P2：知识库检索（`knowledge_lookup`）——已验证

> 2026-09-17。目标：客户问"手续费多少"时，AI 先去我们自己的资料里查，再照着回答，
> 并且"这次引用了哪几条"要能回查。结论：**端到端通过**，答案带出处，检索确实走了向量。

## 1. 交付物

包 `packages/rag`（`@luckycat/dsh-rag`），四个模块各管一件事：

| 文件 | 职责 |
|---|---|
| `src/types.ts` | 只有类型（语料 / 块 / 命中 / 结果） |
| `src/corpus.ts` | 语料加载与校验 + 切块（按空行分段，超长按**码点**硬切） |
| `src/retrieve.ts` | 打分：向量余弦 + 关键词（字符二元组）覆盖，取较优者 |
| `src/bound.ts` | 有界注入：预算内拼接、丢低分、UTF-8 安全截断 |
| `src/index.ts` | 插件本体：注册 `knowledge_lookup` 工具 |

示例语料在 `examples/bank/corpus.json`（5 篇，整体删掉不影响框架本体）。

## 2. 设计决定（每条都有理由）

1. **两路打分取较优**：向量擅长"意思相近"，但对**精确数字与专名**（"千分之一""50 元"）
   会漏；关键词覆盖正好补这点。两路原始值都进结果，能看清是哪一路捞出来的。
2. **语料在加载期同步读**：路径错、JSON 坏、字段缺、id 重复，全部在**启动时**报错，
   不留到客户提问时才失败。
3. **降级要留痕**：向量服务没挂、或者调用失败，就降级成关键词检索，
   并在工具结果里写明 `mode: keyword-only` 与 `degradedReason`——**不假装是向量结果**。
4. **注入有界且规则写死**：
   - 预算包含**包装标签**在内的全部字节（默认 2000）；
   - 超预算**先丢分数最低的**；
   - 只剩一条仍超预算时，按**码点**安全截断（绝不切断一个字）；
   - 预算小到留不下"最小可用长度"（80 字节）时，**什么都不注入**——
     注入一个空引用块只会污染上下文；
   - 丢了几条、有没有截断，全部随结果进日志。
5. **注入是给"后续请求"的**：用 `exec.deferContext()`（loop 在 `tool/result` 之后追加），
   这样后面几轮即使不再调工具，依据仍在上下文里。
6. **工具结果本身带原文**：模型要能直接照着回答；注入块是"续航"，不是唯一来源。

## 3. 端到端证据（真跑的）

```
提问：转账手续费怎么收？单笔最高收多少？

- 费率：境内人民币转账手续费按转账金额的**千分之一**收取（来源：kb-fee#0）
- 单笔上限：单笔手续费最高收**50 元**（来源：kb-fee#1）
简而言之：通过手机银行或网上银行转账免手续费；通过柜面转账按千分之一收费，单笔最高不超过 50 元。
```

自动断言（`scripts/e2e-bank.sh`，查会话日志，不靠肉眼看）：

| 断言 | 结果 |
|---|---|
| A. 会话日志里有 `knowledge_lookup` 调用 | ✅ |
| B1. 日志里有 `<knowledge_reference>` 注入块 | ✅ |
| B2. 注入字节数不超预算 | ✅ 实测 **1117 ≤ 2000** |
| C. 检索模式 = `hybrid` | ✅ 实测 `['hybrid','hybrid']`（模型调了两次工具） |
| D. 回答含语料才有的事实 | ✅ 「千分之一」「50」 |

`mode=hybrid` 这条最关键：它证明**向量检索真的跑了**，不是悄悄降级成关键词。

## 4. 测试证据

- 离线单测 **23 个**（语料校验 6、切块 3、打分 4、有界注入 6、UTF-8 截断 3），全过。
- 变异测试 **2/2 抓获**：
  - 让 `truncateUtf8` 原样返回（不再限字节）→ 4 条用例失败；
  - 忽略循环里的预算判断（命中全塞）→ 5 条用例失败。
- 全仓验收门 **38 条**（含端到端可选门）。

## 5. 踩到的一个 DSH 特性（值得记住）

`ToolExecutionSuccess.value` 的注释明确写着 *"deliberately omitted from durable events"*——
**工具结果的 canonical value 不进会话日志**，落盘的是 `content` 里**渲染后的文本**。
所以"从日志里断言工具返回了什么"必须把文本块当 JSON 解析回来。
我第一版断言直接找 `data.mode`，因此误判为失败；改为解析文本块后就对了。

## 6. 未做 / 已知限制

- **索引不落盘**：每次进程启动重新算块向量（首次调用时算一次并缓存）。语料大起来要接 `ctx.storage`。
- 分批是串行的；没有并发。
- 没有重排（rerank）、没有查询改写、没有按 agent 隔离语料。
- "引用要写出处"目前只是**提示词要求**，没有机械校验；如果合规需要硬约束，
  得在工具结果里加结构化字段并加断言。
- 模型可能**重复调用**工具（本次端到端就调了两次），目前不做去重。
- `minScore` 默认 0.34 是在小语料上试出来的；语料换大了要重新标定。
