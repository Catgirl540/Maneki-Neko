# 招财猫银行 · 功能差距分析

> 对照《虚拟数字银行功能思维导图》（`virtual-digital-bank-features.pdf`，一页六大分支）
> 逐项比对当前项目（演示版 MVP）现状，列出缺口与建议。
>
> 结论速览：**闭环已跑通**（注册开户 → 账户 → 转入/转账 → 卡 → 理财 → 智能客服），
> 大致落在思维导图「落地四期」的第①期；缺的主要集中在
> **多币种储蓄与存钱玩法、信贷与现金流、企业金融、财富自动化与保险、获客裂变、变现与技术/风控底座**。

- 本项目是**比赛演示的虚拟银行 MVP**，不是真实持牌银行。文档区分两类缺口：
  **「演示阶段能低成本补上」** 与 **「真实银行才需要、演示只需占位说明」**。

当前已实现（作为对照基线）：注册即开户、多账户储蓄、转入（绑定卡/工资）、转账（银行账户 / 转数快·跨境支付通，含换汇报价、收款核验、电子回单）、虚拟卡（银联/Visa，开卡收费、锁卡、限额、支付密码取卡密）、理财（风险测评 + 产品超市 R1–R5 + 申购赎回）、消费分析 + 现金流 + 自动扣款、安全中心（改密/换手机号/风控规则/安全评分）、智能客服（真 agent，8 个银行工具）。

## 8. 建议优先级

### A. 演示阶段「低成本、高观感」补充（建议优先做）

1. **多币种账户**：CNY/HKD/USD 余额卡 + 币种划转（汇率可 mock，复用现有换汇报价）
2. **目标分箱 + 凑整转存**：存钱目标进度条 + 每笔消费凑整转入
3. **动态一次性卡号**：生成一张短时效、限额的临时卡号（安全又有记忆点）
4. **现金流**：工资提前支取 / 小额透支（额度、费率、风控拦截展示）
5. **财富自动化**：余额自动申购货基 + 按日计息入账 + 支付时自动赎回
6. **保险**：微型场景险一键投保（1 页完成）
7. **信贷**：BNPL 结账分期 + 秒批消费贷（模拟「评分 → 额度 → 放款 → 按日计息」）
8. **企业版样板**：小微商家后台（对公账户 + 收款码/SoftPOS + 批量发薪）
9. **获客裂变**：邀请码 + 推荐奖励
10. **变现看板**：净利息 / 交换费 / 订阅 / BaaS 四条收入曲线（演示数据）
11. **开户流程可视化**：把 OCR/活体/AML/风险分级做成带状态与耗时的流程页，突出「数分钟」
12. **扩展 agent 能力**：把锁卡、开关自动扣款、开卡、风险测评也接成 agent 工具（目前 8 个工具，缺这几类）

### B. 真实能力/合规相关（演示阶段建议只做「说明 + 占位」）

- 真实 AML / 征信上报 / 监管报送、真实支付清算、加密资产、按揭、BaaS 对外输出
- 牌照、资金托管、利率与合规（图里也强调「以目标市场监管为准」）

### C. 架构上要先补的底座（否则越拖越难）

- **多币种账本模型**：每账户多币种子账本 + 复式记账
- **计息引擎**：按日计息、计提入账（现金管理/透支/贷款都要）
- **事件/审计日志**：全链路留痕，支撑风控复盘与监管
- **可配置风控规则引擎**：规则 + 决策日志（替换现在的写死开关）

## 附：一句话总结

相对这张思维导图，项目**已经跑通第①期闭环**；要往「完整虚拟银行」靠，缺的是：
**多币种与存钱玩法、信贷/现金流、企业金融、财富自动化与保险、获客裂变、变现模型**，
以及支撑它们的**多币种账本、计息引擎、风控与审计底座**。
