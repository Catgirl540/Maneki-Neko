〇、赛题原文要点

构建一个 AI Banking Agent 系统，使用自然语言对话理解用户金融意图，自主规划并执行银行业务操作， 用户可通过 APP / IM 等渠道与 agent 联通。

参赛团队需至少覆盖 3 个核心场景（鼓励全覆盖）。赛题列出的六个参考场景：

#场景子能力
1智能转账按人名 / 手机号 / 备注转账、定时转账、拆分 AA 收款
2账单分析消费分类统计、异常交易识别、月度 / 年度账单报告
3理财操作产品推荐与对比、风险评估、一键申购 / 赎回
4卡片管理卡申请、额度调整、交易限制 / 解锁、卡片挂失
5订阅 / 代扣管理自动识别订阅扣费、续费提醒、一键取消订阅
6跨场景联动检测我爱人生日，当月锁定 1000 元活期，生日前 2 天订购鲜花、蛋糕

「至少 3 个、鼓励全覆盖」是策略支点：别六个全做，做三个稳的加一个出彩的，比六个都半吊子强。

一、要先钉死的：赛题规则本身

这些不问清楚，后面全是白干。找主办方要书面答复：

项为什么要紧
交付物形态交演示视频、可运行系统、还是答辩 PPT？三者工作量差一个数量级
评分维度「理解金融意图」「自主规划」各占多少分？看断言脚本还是看现场演示
演示环境现场有没有网？能否带自己的服务器？模型 API 是否允许外部调用
模型限制指定模型还是自选？能否微调？是否要求国产模型（国内赛道常有此限）
数据合规能否用真实脱敏数据，还是必须全部合成
提交时间与冻结点代码何时冻结，演示当天还改不改
硬件与账号是否要求移动端真机、是否允许用模拟银行后端

二、要备货的四类

1. 模型与密钥（最容易卡死的）

现状：framework/bridge/demo-server.mjs 走 LUCKYCAT_PROVIDER， 默认 openrouter + qwen/qwen3.8-flash；语音另走火山（LUCKYCAT_VOLC_API_KEY）。

要准备：

  • 至少两个 provider 的 API key（主 + 备），现场演示必须能切换
  • 预算：估算一次完整演示（多轮 + 工具调用）的 token 开销，留十倍余量
  • 国内赛道若要求国产模型，现在就去申请通义 / 豆包 / DeepSeek 的 key，审核要时间
  • 离线兜底：断网时的降级话术，或本地小模型

2. 业务数据与语料（真正的工作量）

这是从零要造的，也是评分点所在。没有这些，模型只能编，评测一眼能看穿编造的数字。

场景需要准备的素材
账单分析消费分类体系（MCC 或自定义二级分类）、异常规则（金额突增、异地、非常用商户、深夜）、报告模板
理财操作产品目录（风险等级 R1–R5、期限、业绩基准、费率）、对比维度、适当性匹配规则
订阅 / 代扣商户名 → 订阅服务的识别表（网易云 / Netflix / 房租 / 健身房…）、续费周期推断规则
跨场景联动节日 / 生日日历、礼品商户目录、活期锁定与到期释放规则
智能转账常用收款人别名表（「我妈」→ 账号）、AA 拆单规则（人数、余数分配）

3. 评测集（证明「理解意图」和「自主规划」）

光看演示不够，要一份可回归的题库：

  • 意图识别：同一意图的多种说法
    「给我妈转两千」/「打 2000 块到我妈账上」/「转账，收款方是我妈」
  • 多轮补槽：参数不全时要问什么（「转给张伟」→ 哪个张伟、转多少）
  • 边界与拒答：「把所有钱转出去」「帮我投资赚钱」这类该怎么接
  • 规划链：跨场景联动要求 agent 分解成多步并按时序执行
  • 异常回退：工具调用失败、余额不足、风险测评过期时的处置

4. 合规与安全（评委一定会问，答不上来直接扣大分）

红线要求现状
适当性风险测评未做 / 过期不得申购framework/bridge/wealth-risk.mjs 已做
写操作确认大额转账、申购赎回、卡片挂失必须二次确认clef-reviewer / consent 门禁已有
审计留痕谁在何时对谁做了什么、事由是什么审计日志事由列已补（e2d20e9）
免责与边界不给投资建议、不承诺收益、不代客决策待写进 system prompt
敏感信息卡号 / 安全码脱敏已有

三、要圈定的：现状与缺口

已有（不用重做）

  • Agent 运行时（framework/bridge/）：会话、事件轮询、流式输出、模型降级、断点续聊、同意书门禁
  • 银行工具面（bank-agent.mjs）：转账、卡片申请 / 挂失 / 锁卡 / 限额、代扣开关、理财申购赎回、转人工、卡面信息
  • 理财 API（app/src/api/contract.ts 141–202 行）：产品、持仓、风险测评、现金管理、定投、保险
  • 前端（app/src/components/agent/）：ChatWorkspace + 动作卡片 + 同意书，人机协同链路已通
  • 员工端：工单、审批、审计、客户 360（本人负责部分已基本完成）

缺口（全库检索零命中）

赛题场景现状判断
智能转账转账工具已有；定时转账、AA 拆分没有半
账单分析分类 / 异常 / 报告全无重
理财操作申购赎回、风险测评已有；产品推荐对比没有轻
卡片管理申请 / 额度 / 锁卡 / 挂失已有已备
订阅 / 代扣代扣开关已有；自动识别、续费提醒没有中
跨场景联动全无重但出彩

推荐场景组合

必做三件（底子都在，主要补定时 / AA 和产品对比）：

  1. 智能转账
  2. 理财操作
  3. 卡片管理

压轴一件（视觉冲击最强，最能体现「自主规划」，评委记得住）：

  1. 跨场景联动

若时间有余，再补订阅 / 代扣管理。账单分析工作量最重、演示效果最平，放最后。

四、要排的：人和时间

角色干什么
数据 / 语料账单分类体系、产品目录、订阅识别表、生日日历——最容易被低估，越早越好
评测与演示题库、演示脚本、兜底视频
合规叙事适当性、审计、免责的答辩口径
演示保障备用网络、备用模型 key、录好的兜底视频

五、建议的下一步（三件事）

  1. 把第一节那七个问题发给主办方，拿到书面回复
  2. 敲定三个必做 + 一个出彩的场景组合，别六个全铺
  3. 开始攒数据素材（分类体系、产品目录、订阅识别表、生日日历）——这个不依赖任何技术决策

动工前的最后一份文档是场景规格：每个场景的用户话术样本、需要的工具调用、需要的数据字段。
